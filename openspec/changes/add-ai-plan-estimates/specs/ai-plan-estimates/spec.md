## ADDED Requirements

### Requirement: 예산 조건
시스템은 인원과 전체 기간 예산 및 1인/전체 기준을 모델 요청에 포함해야 한다(SHALL).

#### Scenario: 1인 예산 변환
- **WHEN** 사용자가 3명, 1인 기준 100000원을 입력한다
- **THEN** 요청은 총예산 300000원과 인원 3명을 구별해서 전달한다

#### Scenario: 잘못된 조건
- **WHEN** 인원이 0 또는 소수이거나 예산이 음수·문자열이다
- **THEN** 서버는 모델을 호출하거나 할당량을 차감하기 전에 요청을 거절한다

### Requirement: 추정과 실제 정보 구분
시스템은 AI 금액과 체류시간을 추정으로 표시하고 요금의 단위·수량·산정 가정을 보여야 한다(SHALL). 장소 검색 성공을 요금 검증으로 취급해서는 안 된다(SHALL NOT).

#### Scenario: 미정 요금
- **WHEN** 금액이 없거나 잘못된 범위이다
- **THEN** 미정으로 표시하고 알려진 금액의 부분 합계와 미정 건수를 함께 보여준다

#### Scenario: 확인 상태 위조
- **WHEN** 모델이 요금에 verified 상태나 임의 출처를 추가한다
- **THEN** 이를 공식 확인 근거로 수용하지 않고 AI 추정으로 유지한다

### Requirement: 선택 비용 계산과 저장
시스템은 선택한 장소만 일차별·전체로 합산해야 한다(SHALL). 담기 시 예상 상한과 체류 상한을 계획값으로 저장하고 계산 근거를 메모에 보존해야 한다(SHALL).

#### Scenario: 인원 기준 비용
- **WHEN** 2명이 1인 15000~20000원 식당을 한 번 방문한다
- **THEN** 합계는 30000~40000원이고 담은 장소의 계획 금액은 40000원이며 메모에 1인 단가·2명·AI 추정이 남는다

#### Scenario: 선택 해제와 일차 변경
- **WHEN** 장소를 해제하거나 다른 일차로 옮긴다
- **THEN** 합계와 미정 건수가 선택과 일차에 맞게 바뀌고 실제 지출은 생성되지 않는다

### Requirement: 전체 여행 지역 선택
시스템은 부산 등 시·도 전체를 검색 결과에서 선택할 수 있어야 한다(SHALL). 통계의 시·군·구 분류는 실제 장소 주소를 우선해야 한다(SHALL).

#### Scenario: 부산 전체 선택
- **WHEN** 사용자가 부산을 검색한다
- **THEN** 부산 전체 후보가 자치구보다 먼저 나타나고 한 번의 선택으로 부산 여행을 요청할 수 있다

#### Scenario: 구별 통계 보존
- **WHEN** 부산 전체 여행에 해운대구와 영도구의 확인된 주소가 저장된다
- **THEN** 방문 기록은 각 구로 집계되며 주소 미정 장소는 임의 구에 들어가지 않는다

### Requirement: 일차별 추천 결과
시스템은 결과를 일차별 제목 아래 묶고 선택 장소 수·예상 비용을 함께 표시해야 한다(SHALL).

#### Scenario: 일차 이동
- **WHEN** 1일차 장소를 2일차로 옮긴다
- **THEN** 해당 장소가 2일차 섹션에 표시되고 두 일차의 합계가 갱신된다
