# 설계

기존 3단계 흐름의 2단계에 인원(1~100명), 예산(빈 값 또는 0~1억원), 예산 기준(person/group)을 추가한다. 국내 원화만 사용한다. 서버도 같은 범위를 검사하고 이전 클라이언트의 생략값은 1명·예산 미정·전체 기준으로 처리한다.

응답 items[].estimate.cost는 null 또는 min/max 원화 정수 단가, basis(person/group/room_night), quantity, assumption이다. quantity는 1인당 횟수·일행 이용 횟수·객실 수×박 수이다. person만 인원을 곱한다. stay는 null 또는 분 단위 min/max와 reason이다. 요금 0은 명시적 0원 예상이며 미정 null과 구별한다. 역전된 범위·음수·문자열 금액·잘못된 단위·빈 산정 이유는 미정 처리한다. 예상 요금의 상한은 단가 1천만원·수량 100이고 체류는 5~1440분이다.

비용 계산과 표시 형식은 shared/util/plan-estimate.ts에서 공유한다. 모델의 확인 상태·출처는 수용하지 않는다. 실제 좌표·주소·분류는 기존 장소 검색으로만 확인한다. 검색 결과의 verified는 요금 검증을 뜻하지 않는다.

결과 합계는 선택된 장소와 수정된 일차만 집계한다. 미정 항목 수와 별도 숙박·교통비 미포함을 표시하고 일부 금액만 있는 경우 예산 충족을 보장하지 않는다. 상한이 전체 인원 예산보다 크면 초과를 알린다. 사용자가 담기를 누르면 max 금액과 max 체류시간을 기존 estimatedCost/stayMinutes에 저장하며 단위·수량·범위·AI 추정 표시를 memo에 남긴다. 가계부 지출을 만들지 않는다. DB의 기존 필드로 서버·로컬 저장이 가능하다.

검증은 서버의 잘못된 조건 거절, 응답 정규화, 인원·단위별 곱셈, 선택/일차 변경 집계, 미정과 0원 구별, 저장 후 기준 보존, 모바일/데스크톱 생성 흐름을 포함한다. 실제 Gemini 응답 품질과 실제 요금 정확성은 픽스처 테스트로 검증했다고 보고하지 않는다.

## 추가 사용자 요청: 전체 지역과 일차별 결과

기존 searchRegions에 시·도 전체 후보를 앞에 추가해 자동생성·일반 여행 입력이 함께 사용한다. 통계 원본 REGION_DATA는 변경하지 않는다. createRegion은 시·도 이름에 시·도 코드만 붙이며 통계는 실제 주소의 자치구를 우선한다. 주소 없는 시·도 여행을 임의 첫 구에 집계하던 기대값을 수정한다.

결과는 추천 항목의 일차로 그룹을 만든다. 그룹 내 선택 수와 추정 합계를 표시하고 일차 이동 시 항목이 해당 그룹으로 이동한다. 비용의 곱셈 결과가 DB integer 상한 2147483647을 넘으면 미정으로 처리한다. 예산 0원도 정상 예산이므로 알려진 비용이 있으면 초과를 알린다.
