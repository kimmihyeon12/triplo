## Why
국내 여행자는 AI 추천을 받은 뒤에도 원하는 장소를 골라 지도에 옮기고, 날짜별로 정리하고, 여행 사진을 다른 곳에 기록해야 한다. 선택 가능한 추천과 실제 방문 기록을 연결해 준비 부담을 줄이고 다음 여행으로 이어지게 한다.

## What Changes
- 2026-09-14 사용자 요청으로 Google 로그인·내 정보·로그아웃·인증 가드와 본인 회원탈퇴를 먼저 연결한다. 인증과 여행 DB 저장 완료를 구분하고 회원탈퇴 서버 배포·실계정 검증은 별도 기록한다.
- 상단에는 화면 제목과 T 홈 심볼 또는 뒤로 가기를 사용한다. 현재 시각 기준은 docs/design/DESIGN.md를 따른다.
- Angular 21·NgRx Signals·Zoneless와 기능별 구조를 적용했다. 여행별 상태·실패 입력을 분리하고 응답 역전·저장 충돌 방지를 검증했다. 구조 원본은 docs/architecture/ARCHITECTURE.md, 이행 검증은 tasks 9절이다.
- 수동 알파 다음 개발 우선순위를 지도·장소·경로 실제 연결 → 선택형 AI 실제 연동·디자인 검증 → Supabase 연결로 조정한다. 실제 API와 샘플 화면의 검증 결과는 분리한다(기획안 26절).
- 트리플 공개 맞춤 일정의 단계형 입력·날짜 탭·간결한 화면 구성을 참고한다. 우리 결과는 기본 전체 선택 후 개별 해제·선택한 장소만 담기로 차별화하며 현재 Pretendard·딥 블루 디자인 시스템을 사용한다. 상세 분석은 `docs/트리플-맞춤일정-분석.md`에 기록한다.
- 여행 생성 → 장소·숙소 배치 → 전체 확인 → AI 부분 수정 → 여행 중 사용을 기본 흐름으로 정리한다. 날짜 미정, 식사·휴식 시간, 변경 비교·되돌리기, 지연 대응과 저장 복구를 명시한다.
- 수동 내부 알파 → AI 검증 → 기록·캐릭터 외부 베타 순으로 검증하며 실시간 3D·영상 제작은 핵심 기능의 출시 의존성에서 제외한다.
- 자연어로 숙소 등록 초안을 만들고 숙소·숙박 날짜·일정 영향을 검토한 뒤 사용자 적용으로 저장한다. 숙소 미정 요청은 확인된 후보 선택부터 지원한다.
- 하나의 여행에 여러 지역을 등록하고 같은 날 지역 간 이동을 방문지·숙소 일정과 연결한다. 지역 순서 변경은 영향 확인 후 적용한다.
- 검토용 MVP: 국내 장소 검색·저장, 서울 중심 AI 후보 선택, 여러 박의 날짜별 차량/도보 일정, 숙소 등록과 경로 비교.
- 선택한 다음 목적지를 네이버/카카오 지도에 전달한다.
- 장소 완료·사진·개인 기록지도와 3단계 여행 캐릭터를 연결한다.
- 트리플 여행 가계부를 참고해 여행별 예산·지출 기록과 숙소 요금·예약 정보 연동을 후속 범위로 추가한다. 실제 결제·정산 송금은 하지 않는다.
- 친구 사용 단계에 선택한 일정의 읽기 전용 공유 링크, 로그인·소유자 승인 기반 동행 초대, 결제자·부담 대상별 정산과 수동 수령 기록을 추가한다(기획안 27절). Supabase 권한 검증 후 제공하며 공동 일정 편집·자동 송금은 제외한다.
- 여러 친구가 같은 초대 코드로 참여를 요청하도록 추가한다. 로그인·소유자 승인 후 접근을 허용하고 코드 만료·재발급·중복 요청을 관리한다. 여행 상단에는 D-day·숙박 기간·지역 구분·권한별 지출·동행 프로필 영역을 준비하며 미연결 상태를 실제 데이터와 구분한다(기획안 28절, 세부 배치는 구현 시 확정).
- 장소 정보는 공식 제공 범위만 사용하고 없는 평점·영업정보·예약 가능 여부를 만들지 않는다.
- 3D는 캐릭터·완료 장면에 제한하며 기본 지도·일정 사용을 방해하지 않는다.
- 현재 수동 일정 내부 알파와 AI 샘플 화면을 구현했다. 2026-09-14 사용자 요청으로 Angular 21·NgRx Signals·Zoneless 및 기능별 구조를 적용하고 문서 원본을 docs/ 아래로 정리했다. 완료 범위는 tasks의 실제 검증 기록을 따르며, 실제 LLM·Supabase 여행 DB/RLS와 배포·유료 계정 연결은 이 구현 완료에 포함하지 않는다.

## Capabilities
### New Capabilities
- `travel-planning`: AI 후보 선택, 수동 장소 저장, 당일·여러 박의 날짜별 일정, 숙소 등록·연박·숙소 변경, 순서·이동 계획, 지도앱 연결, 선택형 읽기 전용 공유와 동행 권한.
- `travel-journal`: 장소 방문 상태, 사진 기록, 여행별·지도별 보기, 비공개 데이터.
- `travel-companion`: 방문·여행 완료 기반 성장과 중복 보상 방지.
- `travel-expenses`: 여행별 예산·지출 기록, 카테고리·날짜별 합계, 숙소·장소 연결, 공동 경비 분담·잔액·송금 제안·수동 수령 기록(친구 사용 단계, 2026-09-09 사용자 요청).
### Modified Capabilities
없음.

## Impact
새 웹/PWA 프로젝트에 해당한다.
초기 사용자는 본인과 친구들이며 DB는 Supabase PostgreSQL로 확정한다. 무료 플랜부터 시작하고 로그인·비공개 파일 저장도 Supabase를 사용하는 방향으로 설계한다. 장소·경로·지도 API와 AI 제공자는 실증 후 확정한다. DB 선택과 실제 연결·구현 완료는 구분한다.
일반 공개 API에 없는 네이버 상세 영업정보/카카오 평점은 필수 의존성으로 삼지 않는다.
기획 원문: docs/기획안-v0.1.md. 여러 박 여행과 연박·숙소 변경을 지원한다. 초기 서울 품질 검증과 하루 8장소 제안은 검토 대상이며 여행 기간을 제한하지 않는다.

추가 가입 범위: 카카오·Google 첫 인증 후 /onboarding에서 닉네임 하나만 받는다. 별도 이메일·비밀번호·이름 입력은 받지 않는다. 직접 저장한 닉네임이 있는 기존 회원은 /trips로 바로 이동한다. 닉네임 미완료 사용자는 여행·내 정보에 직접 접근해도 닉네임 설정으로 이동하며, 저장 실패 시 입력을 보존하고 오류 토스트를 표시한다.

카카오 KOE205 대응: 인증 요청은 profile_nickname만 사용하고 이메일·프로필 사진을 추가 요청하지 않는다. 서비스 닉네임은 인증 후 직접 입력한다. 카카오 Developers의 닉네임 동의항목 활성화와 Supabase Kakao 제공자의 Allow users without an email 설정이 필요하다.

## Tailwind 디자인 시스템 전환
사용자 요청으로 전체 화면을 Tailwind CSS로 전환하고 모든 컴포넌트의 HTML과 TS를 분리한다. 기존 시각 방향을 유지하며 공통 UI를 실제 제품과 실험실에서 함께 사용한다.

2026-09-14 스타일 구현 기준: 화면별 CSS 파일을 제거하고 HTML Tailwind 유틸리티로 옮긴다. 공통 UI 및 지도 DOM의 정적 클래스는 TS에서 공유한다. CSS는 테마·기반 스타일·키프레임에 한정한다. 로컬 개발에서 디자인 미리보기를 허용하며 운영·테스트 인증 가드는 유지한다.

## 친구 공동 편집과 비용 기록 확장
최신 사용자 요청으로 링크 소지자의 비로그인 일정 조회, 로그인 후 참여·공동 일정 편집을 구현한다. 기존 승인형·조회 전용 동행은 이 범위에서 대체한다. 일정 예상 비용과 실제 가계부를 분리하고 PNG 일정 내보내기를 추가한다. 서버 배포 여부와 로컬 검증 결과는 구분한다.

실행 범위 정정: 사용자 최신 지시로 DB 연결은 제외하고 친구 초대·가계부·PNG 화면과 로컬 동작을 먼저 구현한다. 실제 공유·참여 권한은 후속 DB 단계다.


2026-09-14 화면 배치 결정: 개별 여행 상세 상단은 `뒤로 · 여행 이름 · 편집 연필 · 참여자 이니셜 · 초대 + · 더보기` 순서로 배치한다. 편집은 숨기지 않으며 가계부는 일정 옆 탭, 이미지 저장은 더보기 메뉴에 둔다. 현재 기기에서는 로그인한 본인의 닉네임만 표시하며 실제 동행 목록은 서버 연결 후 제공한다. 본문 동행 영역과 큰 도구 버튼 나열은 사용하지 않는다.


2026-09-15 기간 선택 UX: 여행 만들기·편집의 기간은 시작일 ~ 종료일을 한 입력 박스로 묶는다. 하나의 달력에서 시작일을 고른 뒤 종료일을 선택하면 양쪽 값을 동시에 적용하고 닫는다. 종료일 선택 전에 닫으면 기존 기간을 유지한다. 시작일보다 앞선 날짜를 고르면 시작일을 다시 잡고 종료일을 기다린다. 당일 여행·월을 넘는 기간·기간 비우기·직접 입력을 지원한다.
