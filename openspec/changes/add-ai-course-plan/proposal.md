# AI 일정 짜기: 시간순 코스와 분류 통일

## Why
2026-09-30 확인 결과 자동생성은 하루 장소 5·식사 3·카페 2곳의 후보 목록이라 어떤 순서·시각으로 다니는지 보이지 않았고, 분류가 장소·식사·카페뿐이라 관광·액티비티·쇼핑·숙소가 구분되지 않았다. 숙소는 아예 추천하지 않았다. 사용자는 시간순 코스에서 원치 않는 곳만 해제해 담고, 장소마다 요금과 요금 기준을 보고 싶다.

## What Changes
- 일정 분류를 관광(`place`)·액티비티·식사·카페·쇼핑·기타·숙소로 넓히고 앱 전체(일정 짜기, 여행 상세, 장소 폼, 챗봇, 통계, 공동 편집 미리보기, 가계부 연결)에서 한 정의로 통일한다. 가계부 라벨 "관광·활동"을 "관광·액티비티"로 맞춘다.
- `stop_kind` 열거형에 `activity`·`shopping`·`other`를 추가한다(값 추가만).
- `ai-plan` 응답에 방문 순서·추천 도착 시각·다음 장소 이동을 추가하고 기본 구성을 하루 코스(관광 2~3, 액티비티 또는 쇼핑 1, 식사 2, 카페 1, 숙소 1)로 바꾼다.
- 결과를 일차별 시간순 카드로 보여 준다. 해제·일차 이동을 지원하고, 빠진 자리를 건너뛴 구간은 모델 이동 대신 직선거리만 표시한다.
- 요금은 모두 AI 추정으로 표시하고 요금 기준(상품·수량)을 보여 준다. 예산 합계는 가계부와 같은 분류(식비·숙박·관광·액티비티·쇼핑·기타)로 나눈다.
- 숙소는 숙박(`stays`)으로 담고 연속 일차의 같은 숙소는 합친다. 추천 시각은 메모에만 남긴다.

## Capabilities
### New Capabilities
- `ai-course-plan`: 시간순 코스 생성·표시·담기와 분류 통일.

## Impact
Angular 일정 짜기·여행 상세·장소 폼·챗봇·통계·가계부 연결, Supabase `ai-plan`·`ai-chat` 함수, `stop_kind` 열거형. 배포 순서는 DB 마이그레이션 → 함수 → 프론트엔드다.

## Scope
검색 연동으로 실제 요금·출처를 조회하지 않는다(사용자 결정). 실제 경로 조회, 출발지 교통비, 해제 후 시각 재배치, 대안 장소 교체는 포함하지 않는다. 설계 근거: `docs/superpowers/specs/2026-09-30-ai-course-plan-design.md`.
