# 알림(웹 푸시) 설계

2026-10-01 작성. 요구사항은 [기획안](../../기획안-v0.1.md) 36절(내 정보·고객 지원)의 알림 항목을 이 문서의 결정으로 바꾼다.

## 1. 목적

사용자 요청(2026-10-01): 웹과 앱 모두에서 알림을 받는다. 보낼 일은 셋이다.

1. **문의에 답변이 달림**: 관리자가 답하면 문의한 사람에게.
2. **새 공지 발행**: 관리자가 공지를 발행하면 알림을 켠 모두에게.
3. **함께 편집 소식**: 내 여행에 누가 참여했거나, 함께하는 사람이 일정·가계부를 고쳤을 때 나머지 멤버에게.

지금 내 정보 화면의 알림 스위치는 "준비 중"으로 잠겨 있다.

## 2. 플랫폼과 한계

이 앱은 설치형 웹 앱(PWA)이다. 서비스 워커가 이미 켜져 있다(`provideServiceWorker`). 그래서 **웹 푸시 하나로** 브라우저와 설치한 앱 모두에 보낸다.

| 환경 | 받는 조건 |
| --- | --- |
| PC 크롬·엣지·파이어폭스, 안드로이드 | 브라우저 탭과 설치한 앱 모두 |
| 아이폰·아이패드 | iOS 16.4 이상에서 **홈 화면에 설치한 앱만**. Safari 탭은 받지 못한다(애플 제한) |

아이폰에서 설치하지 않은 사용자가 알림을 켜려 하면 설치 안내(`/install`)로 보낸다.

## 3. 구조

```text
[앱] 알림 켜기 → 브라우저 권한 → 구독(endpoint·키) → save_push_subscription()
[DB] 답변·공지 발행·참여·일정/가계부 저장 → notification_outbox에 쌓음(같은 트랜잭션)
[pg_cron 1분마다] → Edge Function push-dispatch → 웹 푸시 발송 → 보낸 표시
[서비스 워커] 알림 표시 → 누르면 해당 화면으로
```

- 알림은 **서버 함수 안에서** 쌓는다. 화면이 보내라고 하지 않는다. 관리자 화면을 거치지 않은 변경도, 앱을 닫은 뒤의 발송도 같은 규칙을 따른다.
- 발송은 **outbox + 1분 주기**로 한다. 저장 요청이 푸시 발송을 기다리지 않고, 발송이 실패해도 저장은 성공한다. 같은 묶음 규칙(4절)을 한곳에서 적용한다.
- 쓰는 Supabase 기능: `pg_cron`, `pg_net`(무료 플랜 포함). 발송 키(VAPID 개인키)는 Edge Function 비밀값에만 둔다. 공개키는 런타임 설정(`supabase-config.json`의 `vapidPublicKey`)으로 앱에 준다.

## 4. 알림 종류와 문구

| 종류 | 받는 사람 | 문구(제목 / 본문) | 누르면 |
| --- | --- | --- | --- |
| 답변 | 문의한 사람 | 문의에 답변이 왔어요 / 문의 첫 줄 30자 | `/account/inquiries` |
| 공지 | 공지 알림을 켠 모두 | 새 공지 / 공지 제목 | `/account/notices` |
| 참여 | 여행 주인과 기존 멤버(참여한 사람 제외) | 함께하는 사람이 늘었어요 / ○○님이 「여행 제목」에 참여했어요 | 여행 상세 |
| 일정 고침 | 그 여행의 다른 멤버 | 일정이 바뀌었어요 / ○○님이 「여행 제목」 일정을 고쳤어요 | 여행 상세 |
| 가계부 | 그 여행의 다른 멤버 | 가계부가 바뀌었어요 / ○○님이 「여행 제목」에 지출을 남겼어요 | 가계부 |

규칙:

- **고친 사람 본인에게는 보내지 않는다.**
- **묶기**: 같은 여행·같은 사람·같은 종류(일정 고침, 가계부)는 10분 안에 한 번만 보낸다. 일정을 고칠 때마다 저장이 여러 번 일어나 알림이 쏟아지지 않게 한다.
- 문구에 장소·금액 같은 여행 기록 내용을 넣지 않는다. 잠금 화면에 보이기 때문이다(기본 비공개 원칙).
- 닉네임은 계정 정보의 닉네임만 쓴다.

## 5. 설정

내 정보의 알림 스위치를 연다.

- **알림 받기**(기기마다): 켜면 브라우저 권한을 묻고 이 기기를 구독한다. 끄면 이 기기의 구독을 지운다.
- **받을 알림**(계정마다): 문의 답변·새 공지·함께 편집 소식을 각각 켜고 끈다. 기본은 모두 켬.
- 권한을 거부했으면 스위치 아래에 "브라우저 설정에서 알림을 허용해 주세요"를 보인다. 다시 묻지 않는다(브라우저가 막는다).
- 아이폰 탭에서 켜려 하면 설치 안내로 보낸다.

## 6. 데이터 (마이그레이션)

| 표 | 칸 | 규칙 |
| --- | --- | --- |
| `push_subscriptions` | user_id, endpoint(고유), p256dh, auth, user_agent, created_at | 본인 행만. 쓰기는 함수로 |
| `notification_settings` | user_id, replies, notices, together (기본 true) | 본인 행만 |
| `notification_outbox` | id, user_id, kind, title, body, url, group_key, created_at, sent_at | 사용자는 읽지 못함. 발송 함수만 |

함수: `save_push_subscription`, `delete_push_subscription`, `save_notification_settings`(로그인 사용자), 그리고 내부용 `queue_notification`(기존 서버 함수에서 부름, 묶기 규칙 적용).

쌓는 자리: `admin_reply_inquiry`, `admin_set_notice_published`(초안→발행일 때만), `join_trip`, `save_trip`, `save_expense`, `delete_expense`.

정리: 보낸 지 7일 지난 outbox 행은 지운다. 발송에서 404·410(구독 만료)이 오면 그 구독을 지운다. 계정을 지우면 세 표 모두 함께 지워진다.

## 7. 발송 함수 `push-dispatch`

- pg_cron이 1분마다 `pg_net`으로 부른다. 비밀 헤더로 cron 요청만 받는다.
- 아직 보내지 않은 outbox를 최대 200건 가져와, 받는 사람의 설정이 꺼져 있으면 보내지 않고 보낸 것으로 표시한다.
- 받는 사람의 모든 구독(기기)에 보낸다. 라이브러리는 Deno에서 쓰는 `web-push` 호환 구현.
- 페이로드는 Angular 서비스 워커 형식(`notification.title/body/icon/data.onActionClick`)으로 보내, 누르면 해당 주소를 열거나 이미 열린 창으로 옮긴다.

## 8. 테스트

- 로컬 SQL: 각 함수가 outbox에 맞는 사람·문구로 쌓는지, 본인 제외, 10분 묶기, 설정 꺼짐, 남의 구독 접근 거절.
- 단위: 알림 설정 저장, 구독/해제 흐름(서비스 워커 대역), 아이폰 탭 판별, 권한 거부 안내.
- 발송 함수: 페이로드 모양, 만료 구독 삭제, 설정 꺼짐 건너뛰기(외부 호출 대역).
- e2e: 내 정보에서 알림 켜기·끄기·종류 스위치(테스트 앱은 가짜 구독).
- 실제 기기: 안드로이드 크롬, PC 크롬, 아이폰 홈 화면 앱에서 답변 알림을 받아 눌러 보기(수동, 기록).

## 9. 범위에 넣지 않는 것

- 여행 전날·당일 안내(사용자가 이번에 고르지 않음).
- 앱 안 알림함(받은 알림 목록). 지금은 공지·문의 화면의 새 표시로 충분하다. → 2026-10-06 사용자 요청으로 알림 내역을 추가했다(기획안 44절, OpenSpec `add-notification-inbox`).
- 이메일·카카오 알림톡.
- 조용한 시간(밤 알림 끄기). 쓰다가 필요하면 설정에 더한다.
