# 트립플로 여행 상세·AI 일정 만들기·동행·지출 화면 개선 설계

작성일: 2026-09-09 · 상태: 승인됨(브레인스토밍 완료) · 대상: `app/`(Angular 20, 현재 구조 유지)

**2026-09-09 정정 (구현 도중 사용자 피드백 반영):** 아래 두 가지를 정정한다. 원문은 취소선 없이 정정 표시만 남기고, 실제 지시 사항은 이 정정을 따른다.
1. **그라데이션은 전면 폐기한다.** 딥 보라→마젠타 그라데이션(1·4절에 등장)은 실제 화면에 적용해 본 뒤 사용자가 "그라데이션을 쓰는 것 자체가 과하다"고 판단해 취소했다. The Single Accent Rule에 예외를 두지 않고, 원래 원칙대로 딥 블루(`--accent-deep: #2f5fdb`) 단일 강조색만 쓴다. 여행 상단 정보 카드도, AI 만들기 진입 카드도 흰 카드 + 딥 블루 강조로 만든다.
2. **"여행 상단 정보"(2절)는 여행 상세 화면이 아니라 여행 목록 화면(`/trips`)의 각 여행 카드에 적용한다.** 사용자의 원 의도는 목록 화면의 카드마다 D-day·지출·동행 정보를 보여주는 것이었다. 여행 상세 화면(`/trips/:id`)의 헤더는 기존 그대로(제목·기간·지역·편집 버튼) 유지하고 이번 스펙의 확장 대상이 아니다.
3. **지도 접기·확대 토글은 만들지 않는다(2026-09-10 추가 정정).** 3절의 "지도는 접기·확대가 가능하게" 요구는 사용자 지시로 취소했다. 모바일에서 첫 장소가 보이게 하는 목표는 지도 높이를 고정값으로 줄이는 것만으로 달성하고, 토글 버튼은 추가하지 않는다.


## 범위 밖 (명시적 제외)

- `ARCHITECTURE.md`의 Angular 21 업그레이드, NgRx `signalState` 도입, 기능별 폴더 재배치는 이 작업에 포함하지 않는다. 사용자가 이 설계 적용을 마친 뒤 별도 리팩토링으로 진행하기로 확정했다(2026-09-09). 현재 Angular 20 구조·기존 파일 위치를 그대로 두고 그 위에서 화면을 고친다.
- 실제 Supabase 연결(OAuth 로그인, 서버 저장, RLS), 실제 AI API 호출, 실제 동행 승인·권한 검증, 실제 송금 API는 이 작업 범위에 없다. 이번 스펙은 로컬 상태·화면까지만 다룬다.
- 네이버지도·카카오맵의 실제 브랜드 로고 이미지는 사용하지 않는다. 브랜드 색상만 반영한다.

## Why

1. `docs/디자인-비교-검토-2026-09-09.md`가 지적한 대로, 모바일 첫 화면에서 첫 장소가 보이지 않고 카드마다 편집 동작이 과도하게 반복 노출된다.
2. `docs/TourJ-참고와-AI-입력방식-검토.md`가 제안한 3단계 AI 입력 방식이 미확정 상태였다. 이번 작업에서 확정 반영한다(그라데이션 강조 제안은 검토 후 채택하지 않았다 — 2026-09-09 정정 참고).
3. 현재 화면에는 동행 표시, 지출 요약, AI 일정 만들기 진입점이 없다. `PRODUCT.md`의 미결 서비스명은 해소됐지만(트립플로), 하단 4개 메뉴 중 구현된 것은 여전히 '트립플로' 탭 하나뿐이다.
4. 메인 강조색을 코랄에서 딥 블루로 바꾼 결정(2026-09-09)을 그대로 유지하며, `DESIGN.md`의 "The Single Accent Rule"에 예외를 두지 않는다.

## 1. 색

- 단일 강조색은 딥 블루(`--accent-deep: #2f5fdb`) 하나다. 탭 밑줄, 링크, 포커스 링, 지도 마커, 순번 배지, 일반 버튼(저장·취소·삭제·추가 등), 여행 목록 카드의 D-day 배지·지출 강조·AI 만들기 진입 카드까지 전부 이 단색을 쓴다.
- 그라데이션은 쓰지 않는다(2026-09-09 정정: 실제 적용 후 사용자가 취소). `DESIGN.md`의 The Single Accent Rule에는 예외를 두지 않는다.

## 2. 여행 카드 정보 확장 (여행 목록 화면 `/trips`)

이전 대화에서 공유된 참고 스크린샷(다크 배경 여행·정산 앱)의 정보 배치 구조를 참고하되, 다크 테마·로고·캐릭터는 가져오지 않는다. 참고하는 것은 아래 정보 위계뿐이다. **적용 대상은 여행 목록 화면(`/trips`)의 각 여행 카드다.** 여행 상세 화면(`/trips/:id`)의 헤더는 기존 그대로 두고 확장하지 않는다.

- 여행 제목, 기간(N박 N+1일 또는 당일 0박 1일), 날짜 범위를 카드 안에서 구분해 표시한다.
- 상태 배지는 `예정 D-N` / `진행중 D-day` / `여행 중 · N일차` / `일정 날짜 지남` 네 가지를 구분한다(기획안 356절 로직 재사용). 종료 예정일 경과를 사용자 명시적 '여행 완료'와 자동으로 동일시하지 않는다.
- 지역 순서는 첫 지역 → 다음 지역 형태로 카드 안에 구분 표시한다(예: 강릉 → 속초). 지역별 세부 탭 여부는 이번 스펙에서 정하지 않고 기존 `DayMapModel` 구조를 유지한다.
- 지출 요약(계획 대비 실제 지출, 미설정이면 '미설정'으로 표시하고 0원으로 위장하지 않음)을 카드 안에 표시하고, 누르면 지출·정산 화면으로 이동한다.
- 원형 동행 프로필 자리와 [+ 초대] 버튼을 카드 안에 배치한다. 실제 동행이 없으면 기본 아이콘 하나와 "동행 기능 준비 중" 문구만 보이며, 가짜 참여자를 만들어 채우지 않는다.

## 3. 일정 화면 개선

`docs/디자인-비교-검토-2026-09-09.md`의 우선 개선 1~3번을 그대로 적용한다.

- 모바일 390×844에서 첫 장소 이름과 주요 정보가 스크롤 없이 보이도록 머리글·탭·지도 높이를 줄인다. 지도 높이는 고정값으로 줄이며, 접기·확대 토글은 제공하지 않는다(2026-09-10 사용자 지시로 제외).
- PC(900px 이상)는 지도와 일정 목록을 나란히 배치한다.
- 장소 카드의 기본 노출 동작은 [지도 보기]와 [더보기]로 줄인다. 위/아래 순서 변경, 편집, 제외는 '순서 편집 모드'로 들어갔을 때만 노출한다. 키보드 접근성과 `aria-label`은 유지한다.
- 네이버지도·카카오맵 링크, 주소 복사는 더보기 메뉴 안으로 옮긴다.
- 전체 보기의 날짜별 요약, 연박·숙소 변경 표시 로직은 변경하지 않는다.
- 장소 추가 폼(`stop-form-page.ts`)은 검색·이름·날짜를 기본 노출하고, 체류시간·고정 시각·메모는 접힌 '선택 정보 더보기' 아래로 옮긴다.

## 4. AI 일정 만들기 (신규 화면, 목데이터 기반)

`docs/TourJ-참고와-AI-입력방식-검토.md`의 제안을 확정한다.

- '발견' 탭에 흰 카드 + 딥 블루 강조(`btn--primary` 계열)로 진입점을 둔다. 지금은 '발견' 탭 자체가 없으므로 이번 스펙에서 최소 형태로 함께 만든다(하단 4개 메뉴 중 '발견'과 '트립플로' 2개만 실제 라우트, 나머지 2개는 후속).
- 첫 생성은 3단계로 구성한다.
  1. 지역·방문 순서·날짜(날짜 미정 허용).
  2. 동행·취향·이동수단·일정 밀도(선택 항목, 건너뛰기 가능, 기본값 존재).
  3. 꼭 갈 장소·기존 숙소/예약·추가 요청(선택 항목, 없으면 건너뜀).
- 마지막에 조건 요약 화면에서 각 항목을 눌러 직접 수정한 뒤 [AI 일정 만들기]를 눌러야 생성이 실행된다.
- 재생성은 이전 조건이 채워진 요약 화면에서 시작한다. 처음부터 3단계를 반복하지 않는다.
- 결과 화면의 검증된 방문 항목은 기본 전체 선택 상태로 시작한다. 사용자가 원치 않는 항목을 해제한 뒤 [선택한 장소 N개 일정에 담기]를 눌러야 실제 여행에 반영된다. 전체 선택은 자동 저장이 아니다.
- 단계 이동, 체크 토글, 요약 화면 진입/수정에는 AI를 호출하지 않는다. AI 호출은 최종 [AI 일정 만들기] 버튼 클릭 한 시점뿐이다.
- 실제 LLM 키가 없으므로 결과는 명확히 "샘플 결과"로 라벨링된 고정 목데이터를 사용한다. 실제 연동으로 보고하지 않는다.
- 기존 숙소·고정 일정과 입력 상태는 AI 흐름 진입/이탈 시에도 보존한다.

## 5. 동행 초대 (화면·로컬 상태만)

- 여행 목록 카드(2절)의 프로필 영역과 [+ 초대] 버튼에서 초대 화면으로 진입한다.
- 초대 화면은 8자리 코드(`ABCD-EFGH` 표시 형식) 발급 UI와 "코드로 참여" 입력 UI를 모두 제공하되, 실제 발급·검증 로직은 로컬 상태의 목업으로만 동작한다.
- 승인된 동행과 승인 대기 동행을 구분해서 목록에 표시한다. 지금은 실제 서버가 없으므로 이 목록은 데모용 로컬 상태이며, 화면에 "Supabase 연결 전 미리보기" 같은 명확한 표시를 둔다.
- 실제 코드 만료·재발급·중복 요청 방지·멤버 제거 권한 검증은 이번 범위에 포함하지 않고, `PRODUCT.md`·OpenSpec에 후속 작업으로 남긴다.

## 6. 지출·정산 (화면·로컬 상태만)

OpenSpec `specs/travel-expenses/spec.md`의 요구사항을 화면과 로컬 상태 수준까지 구현한다.

- 지출 기록(금액·카테고리·날짜·메모), 예산 대비 사용액 표시, 일정·숙소 연결을 구현한다.
- 결제자 1명과 부담 대상, 균등/직접 분배를 지정하는 UI를 구현하고, 분배 합계와 지출액이 다르면 저장을 막는다.
- 사람별 잔액과 송금 제안 금액을 계산해 표시한다.
- 수동 수령 기록·취소·재계산 UI를 구현한다.
- 개인 지출은 작성자만 보고, 공동 지출·분담·정산만 동행에게 보이는 구조를 화면 단에서부터 지킨다(실제 서버 RLS는 후속).
- 데이터는 기존 `TripRepository` 패턴을 확장한 로컬 저장으로 유지한다. 미연결·미설정 금액은 "미설정"으로 표시하고 0원으로 위장하지 않는다.

## 7. 지도 버튼 정비

- 네이버지도 버튼: 네이버 브랜드 그린(`#03C75A`) 배경 + 흰 아이콘.
- 카카오맵 버튼: 카카오 브랜드 옐로(`#FEE500`) 배경 + 잉크색 아이콘(밝은 배경이라 흰 글자는 대비 부족).
- 아이콘은 기존 `IconComponent`의 `pin`을 재사용한다. 각 서비스의 실제 로고 모양은 임의로 그리지 않는다.
- 두 버튼 모두 `btn--sm`(36px) 크기로 통일한다.
- `item__links` 행에서 지도·주소 복사 버튼군과 위/아래·편집·제외(`btn--icon`, 40px) 버튼군을 시각적으로 분리한다(3절에 따라 후자는 순서 편집 모드로 이동하므로 실질적으로 행이 나뉜다).
