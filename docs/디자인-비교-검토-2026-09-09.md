# 현재 디자인과 트리플 비교

검토일: 2026-09-09. 독립 평가 A(디자인·소스·시각 검토)와 B(자동 검사·브라우저 근거)를 분리해 진행했다. 이번 결과는 검토 의견이며 제품 코드나 기획상의 디자인 방향을 변경한 것이 아니다.

현재 앱은 기본적인 정리와 편집 구조가 갖춰져 있다. 트리플에 가까워지려면 색보다 **첫 장소가 보이는 위치, 카드의 정보 위계, 항상 보이는 편집 동작 수**를 먼저 개선해야 한다. 현재 날짜별 화면은 일정을 읽기보다 관리 기능을 찾는 데 시선이 많이 분산된다.

## 비교 근거와 한계

- 현재 앱: `app/src/app/features/trips`, 1440×1000 PC·390×844 모바일. 여행 목록·만들기·전체 보기·날짜별·숙소·장소 추가·숙소 추가를 캡처했다. 별도 포트 4400, 테스트 구성, 별도 브라우저 저장소의 3박 4일 강릉·속초 샘플을 사용했다.
- 지도는 테스트 픽스처의 회색 캔버스·마커다. 실제 카카오 지도·지형·경로 품질을 평가하거나 연동 완료로 판정하지 않는다. 샘플 장소 좌표는 테스트 근사값이다.
- 트리플: [공개 맞춤 일정 페이지](https://triple.guide/trips/promotion/customized-schedule)와 같은 날 직접 확보한 390×844·1440×1000 캡처. 네이티브 앱·로그인 후 일정 편집은 미검증이다.
- 현재 앱의 수동 일정 편집과 트리플의 추천 결과는 목적이 다르다. 트리플의 동작 수를 그대로 복제하지 않고 읽기와 편집의 우선순위를 비교한다. AI 단계 질문·선택 담기는 현재 앱에서 아직 구현을 확인하지 못한 후속 화면이다.
- 검토 시점 실제 CSS 강조색은 파랑 `#2f5fdb`다. 이전 코랄 지침과 일부 문서가 다르므로 이 검토만으로 색상을 되돌리지 않는다. 문서 동기화는 별도 정리 대상이다.

## 우선 개선할 항목

1. **P1 — 첫 장소가 첫 화면에 없다.** 샘플의 날짜별 목록은 모바일·PC 모두 약 y824부터 시작한다. 모바일 844px 높이에서는 하단 고정 버튼 위에 첫 장소가 보이지 않는다. `trip-detail-page.ts`의 머리글·탭·지도 전후 간격과 900px 이상 배치를 조정한다. 모바일 지도는 약 160~200px의 축약 보기와 확대 동작을 비교하고, PC는 지도·목록을 병렬로 구성한다. 확인 기준은 390×844에서 첫 장소 이름과 주요 정보가 스크롤 없이 보이는지다. 관련: `app/src/app/features/trips/trip-detail-page.ts:211`, `:714`, `:933`, `app/src/app/shared/trip-map.ts:71`. 제안 작업: Impeccable layout/adapt.
   - **2026-09-10 확정**: 지도 접기·확대 토글은 사용자 지시로 만들지 않는다. 지도 높이를 고정값으로 줄이는 것만으로 첫 장소 노출 목표를 달성한다.
2. **P1 — 일정을 읽는 중에도 편집 동작이 반복된다.** 각 장소에 지도 링크 둘과 순서·편집·제외 버튼이 계속 붙는다. 날짜·장소를 읽을 때의 시선이 분산된다. 기본 카드에는 지도 보기와 더보기를 두고, 순서 조정 모드에서 위/아래 동작을 노출한다. 접근 가능한 이름과 키보드 대안은 유지한다. 주소 복사·지도 앱 선택은 상세 메뉴로 모은다. 관련: `trip-detail-page.ts:310`, `:315`, `:327`. 제안 작업: Impeccable distill.
3. **P2 — 장소 추가 폼의 선택 입력이 길다.** 390px 캡처의 전체 높이는 약 1526px이며 종류·검색·이름·주소·지역·날짜·체류·고정 시각·메모가 한 번에 펼쳐진다. 검색/직접 입력으로 장소를 고르고 날짜를 정하면 저장할 수 있게 하며, 체류시간·고정시각·메모는 선택 세부로 묶는다. 검색으로 얻은 정보는 입력 중복을 줄이고, 저장 버튼은 키보드와 겹치지 않는 하단 위치를 검토한다. 관련: `app/src/app/features/trips/stop-form-page.ts:28`. 제안 작업: Impeccable distill/clarify.
4. **P2 — 미확인 설명과 개발 설정 안내가 제품 화면에 섞인다.** 위치·이동시간을 미확인으로 표시하는 원칙은 유지한다. 다만 반복 설명은 지도 범례와 일별 요약에 모으고 각 항목에는 짧은 상태를 둔다. 지도 미설정 분기의 파일 경로·JavaScript 키 안내는 개발 문서로 옮기고 사용자 화면에는 수동 입력·외부 지도 열기 등 가능한 행동을 안내한다. 파일 경로 노출은 소스에서 확인했으며 이번 테스트 지도 화면에서는 그 분기를 실행하지 않았다. 관련: `app/src/app/shared/trip-map.ts:29`, `:31`. 제안 작업: Impeccable clarify.
5. **P2 — 여행 장소보다 관리 정보가 강하다.** 여행 앱다운 느낌은 배경색만으로 생기지 않는다. 장소 이름·분류·선택 이유가 먼저 읽히도록 구성하고 실제 제공 가능한 사진이 있을 때 작은 썸네일을 더한다. 사진이 없으면 안정적인 장소 아이콘을 사용한다. 영업정보·평점·추천 이유를 사실처럼 지어내거나 트리플 자산을 복사하지 않는다. 제안 작업: Impeccable layout/typeset.

## 유지할 강점

- 전체 보기에서 여러 날짜의 장소와 숙박을 함께 읽고, 연박·체크아웃·숙소 변경을 구분할 수 있다. 현재 앱의 복수 지역·여러 박 요구에 맞는 구조다.
- 헤더·흰 표면·둥근 컨트롤과 고정 추가 버튼에 일관성이 있다. 전체 테마를 다시 만드는 것보다 정보 위계 개선의 효과가 크다.
- 미배치와 미확인을 숨기지 않고 표시한다. 이 정보를 없애기보다 필요한 위치에 짧게 정리해야 한다.

## 사용성 평가

평가 A의 관찰·소스 기반 휴리스틱 점수다. 사용자 실험 결과나 트리플과의 객관적 성능 점수가 아니다. 4점은 강함, 0점은 심각한 문제이며 직접 검증하지 않은 실패 복구는 평가에서 제외했다.

| 기준 | 점수 /4 | 근거 |
| --- | --- | --- |
| 시스템 상태 | 3 | 기기 저장·선택 탭·미확인이 표시됨 |
| 현실 언어 | 2 | 여행 용어는 명확하지만 개발용 지도 키 안내가 섞임 |
| 사용자 통제 | 3 | 편집·순서·제외를 제공하나 읽기 흐름과 분리 필요 |
| 일관성 | 3 | 화면별 컨트롤·표면이 대체로 일관됨 |
| 오류 예방 | 3 | 필수 입력·날짜·선택 항목 구분이 있으나 전체 예외 실증은 아님 |
| 기억 부담 감소 | 2 | 장소 식별보다 상태·동작을 먼저 읽게 됨 |
| 효율 | 2 | 길어진 폼·반복 동작·PC 수직 배치 |
| 미학·최소주의 | 2 | 여백은 정리되었지만 첫 장소까지의 공간과 보조 정보가 큼 |
| 오류 복구 | 미평가 | 실패 후 저장 복구를 이번 디자인 검토에서 직접 실행하지 않음 |
| 도움말 | 2 | 설명은 있으나 사용자 행동과 개발 설정이 혼재 |

처음 사용자는 많은 선택 입력을 필수로 오해할 수 있다. 여행 중 한 손으로 보는 사람은 첫 장소까지 스크롤해야 한다. 반복 편집자는 카드마다 같은 도구를 읽는다. 반면 전체 보기의 하루 단위 요약은 일정 준비 후 확인 부담을 줄인다. 핵심 인지부하는 정보량 자체보다 읽기와 편집이 같은 시점에 노출되는 데 있다.

## 자동 검사와 검토 범위

독립 평가 B가 trips와 shared를 대상으로 실행한 Impeccable 검사 결과는 `[]`, 지적 0건이다. 별도 브라우저의 빈 목록에서 검사 스크립트 주입도 성공했고 콘솔에 `No anti-patterns found.`가 기록되었다. 이는 레이아웃 적합성·접근성 전체 통과나 실제 지도 동작을 보장하지 않는다. 사용자의 브라우저에 오버레이를 띄웠다고 주장하지 않는다.

자동 검사 근거: `output/playwright/design-review/detector.json`. 시각 캡처 10장은 같은 폴더에 있고 재현 스크립트는 `capture.cjs`다. 결과 이미지를 후처리하거나 제품 화면을 수정하지 않았다. 전체 페이지 캡처에서 고정 하단 바는 캡처 당시 뷰포트 위치에 나타나므로 가림 판단은 `*-viewport.png`를 기준으로 한다.

## Claude에 전달할 수정 범위

> 현재 PRODUCT.md·DESIGN.md와 실제 CSS의 최신 사용자 선택을 먼저 확인해. 이 검토 보고서의 1~3번을 우선 적용하되 기존 데이터·일정·숙박 규칙을 유지해줘. 모바일은 첫 화면에 첫 장소가 보이게 하고, PC는 지도와 목록을 나란히 배치해줘. 보조 편집 버튼과 선택 입력을 접어서 읽기 흐름을 단순하게 해줘. 미확인 정보의 정직한 표시와 키보드 조작은 유지하고, 기능·디자인 변경을 관련 기획·OpenSpec·디자인 문서에 기록해줘. 실제 API 연결 검증과 테스트 지도 캡처는 구분해줘.

이 명령은 다음 수정에 사용할 제안이며 이번 비교 작업에서 실행하지 않았다.
