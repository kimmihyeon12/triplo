# Product

2026-09-30 코드 기준: 운영은 Supabase 여행·가계부 저장과 초대 멤버 공동 편집을 사용한다. AI 일정·채팅·영수증 인식은 Edge Function을 거친다. 대화·문의 기록은 계정별 기기 저장이며 AI 응답 생성에는 대화와 여행 문맥이 전송된다. 테스트는 로컬 저장소와 고정 외부 응답을 사용한다. 원격 배포 상태는 이번 문서 갱신에서 재확인하지 않았다.

이 파일은 사용자 인터뷰 없이 `docs/기획안-v0.1.md`(2026-09-09)와 OpenSpec `plan-travel-companion-mvp`에서 도출했다. 작성 당시 지침에 따른 도출 기록이며, 현재 공통 작업 규칙은 루트 AGENTS.md를 따른다. `[추론]` 표시가 붙은 항목은 문서에서 직접 확인하지 못한 추론이다.

## Platform

web

## Stack

Angular 21(standalone, Zoneless) + NgRx Signals 21 + TypeScript. 내부 알파는 Angular 20으로 시작했고 2026-09-14 기존 아키텍처 결정에 따라 업그레이드했다. 클라이언트 중심 웹앱이며 실제 버전과 검증 기록은 package.json·OpenSpec tasks 9절을 따른다.

## Users

- 1차 사용자: 프로젝트 소유자 본인과 친구들. 1인·커플·친구 단위의 국내 자유여행을 각자 계획한다. 개인 여행을 관리하거나 초대 멤버와 일정·가계부를 함께 편집한다. 실시간 변경 구독은 후속 범위다.
- 사용 상황: 여행 전 집·카페에서 모바일 또는 PC로 일정을 만들고, 여행 중에는 모바일로 오늘 일정과 다음 목적지를 본다. 한국어 우선.
- 해내려는 일: 원하는 장소만 골라 현실적인 날짜별 일정과 숙소를 정리하고, 전체를 한눈에 확인한 뒤 원하는 부분만 안전하게 고친다.

## Product Purpose

AI가 제안한 장소 중 마음에 드는 곳만 골라 현실적인 여행 일정을 만들고, 다녀온 사진과 추억으로 나만의 지도와 작은 여행 친구를 키우는 국내 여행 비서. 성공 지표는 실제 여행을 완료하고 사진 또는 메모를 남긴 여행 수다. 현재 단계(내부 알파)의 성공은 여행 생성 → 장소·숙소 등록 → 전체 보기 → 같은 기기에서 재열기를 처음 사용자가 도움 없이 수행하는 것이다.

## Positioning

추천 결과를 자동으로 일정에 넣지 않고 사용자가 고른 것만 저장하며, 확인되지 않은 영업정보·이동시간·좌표를 절대 확정값처럼 표시하지 않는다. 여러 박·복수 지역·숙소 변경·숙소 미정을 하나의 여행 안에서 정직하게 표현하는 일정 도구가 핵심이고, 사진 지도와 캐릭터는 그 뒤에 온다.
2026-09-09 사용자 추가 결정: AI 일정 만들기는 한 번에 긴 질문을 던지지 않고 단계별로 조건을 받는다. 추천 결과의 검증된 방문 항목은 처음에 전체 선택하고, 사용자가 원치 않는 항목을 해제한 뒤 선택 항목만 명시적으로 담는다. 전체 선택은 자동 저장이 아니다. 화면별 적용 규칙은 기획안 25절에 있다.

## Operating Context

- 데이터: 여행, 순서 있는 지역, 날짜별 장소·활동(식사·휴식·여유), 체크인·체크아웃 날짜를 가진 숙박. 알파는 여행·가계부를 로그인 계정별 Supabase PostgreSQL + Auth에 저장하고, 챗봇 대화·문의는 기기에 계정별로 둔다. 테스트 앱과 디자인 미리보기는 기기에 저장한다.
- 외부 연결: 네이버지도·카카오맵으로 다음 목적지 열기(설치되지 않으면 웹 지도·주소 복사). 카카오 장소 검색·지도와 AI(Edge Function 경유)를 연결했다. 연결별 실제 검증 범위는 DEVELOPMENT.md를 따른다.
- 하단 주요 메뉴 4개(기획): 발견 / 트립플로 / 기록지도 / 여행 친구. 이는 장기 메뉴 기획이다. 현재 여행·AI 일정·채팅·방문 통계·계정 경로를 제공하며 이 4개 메뉴 전체를 구현한 상태는 아니다.
- PC는 지도와 일정 목록을 나란히, 모바일은 하단 시트와 날짜 탭, 태블릿은 두 영역 폭 조정(기획 10절). 일정 목록이 화면의 중심이다.

## Capabilities and Constraints

- 지원: 당일(0박 1일)부터 여러 박까지, 날짜 미정 초안, 미배치 장소, 복수 지역, 하루 두 지역, 연박·숙소 변경·숙소 미정, 순서 변경(버튼·키보드), 장소 제외, 체류시간·메모·고정 시각, 식사·휴식·여유시간, 전체/날짜별/숙소 보기, 충돌 표시, 저장 상태·실패 보존·재시도.
- 제약: 위치·이동시간이 미확인인 항목은 미확인으로 유지한다. 도착 시각을 추정해 제시하지 않는다. 기간 단축·지역 삭제 시 데이터를 자동 삭제하지 않는다. 드래그만으로 조작하지 않는다.
- 용어: 여행(Trip), 지역(Region), 장소(Place stop), 활동(식사·휴식·여유), 숙소/숙박(Accommodation stay), 미배치, 미정, 미확인, 충돌.
- 확정: 카카오 지도·장소 검색, Edge Function 경유 Gemini AI, 챗봇 구름이 2D 이미지. 미결: 월 운영 예산, 일반 공개 시점, 경로 API와 3D 성장 기능.

## Brand Commitments

- 현재 로고 적용안(2026-09-10): 그림 심볼 대신 서비스명 ‘트립플로’를 표시하는 워드마크. 이전의 ‘로고 옆 글자 제거’ 지시는 최신 이름 중심 로고 요청으로 대체되었다. 최종 브랜드 확정과 현재 시범 적용은 구분한다.
- 일반 편집 화면과 워드마크는 그라데이션 없이 딥 블루 단색을 쓴다. 현재 구현된 티켓형 로그인·초대·설치 화면과 AI 진입 카드의 제한된 그라데이션은 예외적인 표현으로 문서화하며, 저장·추가·선택 조작의 색상 의미를 대신하지 않는다.

- 서비스명은 트립플로(Triplo, 2026-09-09 확정)다. 작업 폴더명 travel-companion은 여전히 임시 기술 식별자다.
- 현재 챗봇은 구름이 2D 전신 이미지를 사용한다. 배치·크기는 DESIGN.md의 현재 기준을 따른다. 기록 보상과 연결한 3D 캐릭터 성장은 후속 범위다.
- 어조: 확인된 것과 확인되지 않은 것을 구분해 말한다. 없는 정보를 만들지 않는다.
- 시각 방향: Pretendard 한 가족, 딥 블루 강조, 중성 배경·흰 카드·구분선·밑줄 탭을 사용한다. 실제 토큰과 공통 UI 규칙은 docs/design/DESIGN.md를 따른다. 장식용 서체와 스티커는 사용하지 않는다.

## Product Principles

1. 사용자가 고른 것만 저장하고, 시스템이 몰래 바꾸지 않는다.
2. 확인되지 않은 정보는 미확인으로 보이게 둔다.
3. 빈 날짜·숙소 미정·미배치가 있어도 저장을 막지 않는다.
4. 기간·지역 변경으로 데이터를 잃지 않는다.
5. 핵심 일정 편집은 지도·3D·캐릭터보다 우선하며 그것들에 방해받지 않는다.
