# 트립플로 디자인 시스템

제품 방향은 [PRODUCT.md](PRODUCT.md), 구조·코드 규칙은 [ARCHITECTURE.md](../architecture/ARCHITECTURE.md)를 따른다. 이 문서는 현재 UI의 사용 규칙을 관리한다. 색상·크기 값을 중복 선언하지 않고 [theme.css](../../app/src/styles/theme.css)를 실행 원본으로 사용한다. 실제 예제는 [실험실](http://localhost:4200/lab)에서 확인한다.

## 시각 방향

채팅 메시지는 18px 모서리를 사용한다. 구름이 답변·응답 대기에만 아바타 방향의 작은 꼬리를 붙인다. 꼬리는 메시지와 같은 흰 배경·옅은 테두리로 이어지며, 사용자 메시지는 파란 배경에 꼬리 없이 표시한다.

챗봇의 확정 캐릭터는 구름이 전신 2종이다. 작은 미소(`companion-cloud-sorry-v1.png`)는 대화·응답 준비·추천 결과, 졸림(`companion-cloud-sleepy-v1.png`)은 진입 버튼에 쓴다. 몸통을 자르는 크롭을 금지하며 대화 48px·헤더 56px로 표시한다. 채팅 버튼은 파란 배경·흰 ‘AI 채팅’ 글자(13px), 높이 44px, 좌측 여백 52px·우측 14px이고 56px 구름이를 왼쪽 아래 1px에 둔다. 중복 말풍선 아이콘은 넣지 않는다. 상세에서는 기존 일정 추가 바 위 위치와 안전 영역을 유지한다. 적용 근거와 검증은 [구름이 적용 기록](references/cloud-chat-preview.md)에 통합한다.

밝은 중성 배경 위 흰 카드, 명확한 텍스트 위계, 딥 블루 주 동작을 사용한다. 제목과 본문은 Pretendard 한 가족이며 숫자는 tabular-nums로 정렬한다. 상단에는 화면 제목을 표시하고 홈 링크에는 T 심볼을 사용한다. 뒤로 이동이 필요한 화면은 뒤로 가기 버튼을 표시한다.

카드에는 `rounded-panel`과 `shadow-panel`을 사용하고 내부 목록은 `border-border` 구분선으로 나눈다. 카드 테두리와 그림자를 불필요하게 겹치지 않는다. `shadow-panel`의 첫 값인 1px 윤곽선은 옅게 둔다. 짙으면 테두리를 그은 것처럼 보여 카드가 떠 있지 않고 종이 조각으로 읽힌다(2026-09-21 0.05에서 0.025로 낮춤). 이모지·스티커·장식용 서체를 제품 조작 요소로 쓰지 않는다.

| 텍스트 | `text-ink` 본문·제목, `text-ink-2` 보조, `text-ink-3` 힌트 |
| 주 동작·현재 선택 | `accent-deep`, `accent-deep-hover`, `accent-tint` |
| 숙소 | `stay-ink`, `stay-tint` |
| 미확인·주의 | `warn-ink`, `warn-tint` |
| 오류·충돌 | `danger-ink`, `danger-tint` |
| 완료 | `ok-ink`, `ok-tint` |
| 일정 분류 | 장소 `place-ink`·`place-tint`, 식사 `meal-ink`·`meal-tint`, 카페 `cafe-ink`·`cafe-tint`, 지역 `region-ink`·`region-tint` |
| 간격 | 기본 단위 4px. 화면 여백 16px, 넓은 화면 24px |
| 모서리 | panel 16px, control-lg 12px, control 10px, cell 8px |
| 서체 | `font-body`, `text-12`~`text-34`. 기본 본문 15px, 필드 라벨·안내 13px, 주요 화면 제목 22px |
| 반응형 | sm 420px, md 720px, lg 960px. 일반 콘텐츠 최대 960px, 인증 폼 최대 420px |

색만으로 상태를 구분하지 않고 텍스트·아이콘을 함께 사용한다. 숙소색·주의색·완료색을 일반 강조색으로 돌려 쓰지 않는다. 같은 이유로 일정 분류에도 완료색·숙소색을 빌려 쓰지 않고 분류 전용 색을 쓴다. 소셜 로그인은 해당 제공자의 브랜드 토큰을 사용한다.

그라데이션은 선택 날짜의 `--selected-fill`, AI 만들기 진입의 `--ai-fill`, 티켓형 로그인·초대·설치 화면의 헤더에 한정한다. 일반 저장·추가 버튼과 워드마크는 단색이다. 광범위한 편집 카드와 일반 브랜드 배경에 그라데이션을 확대하지 않는다.

통계 지도 `/stats`의 바다는 사용자가 지정한 2.5D 원본 재현을 위해 지도 전용 `map-water/light` 토큰의 밝기 변화를 허용한다. 흰 큐브 지형과 `map-visit-low/middle/high` 청록 군집은 지역별 방문 합계 전용 표현이며 일반 버튼이나 브랜드 배경에 재사용하지 않는다. 방문색의 현재 값과 근거는 아래 2026-09-21 절을 따른다.

## 구현 위치

- [styles.css](../../app/src/styles.css): Tailwind·기반 스타일의 진입점.
- [theme.css](../../app/src/styles/theme.css): 색상·서체·간격·모서리·그림자 토큰.
- [base.css](../../app/src/styles/base.css): 문서 기본값·리셋·기본 포커스.
- [effects.css](../../app/src/styles/effects.css): 키프레임과 모션 감소 처리.
- `app/src/app/shared/ui/<이름>/`: 공통 컴포넌트의 HTML·TS와 필요 시 `.styles.ts` 클래스 모음.
- [map-marker-styles.ts](../../app/src/app/features/places/util/map-marker-styles.ts): 지도 SDK가 생성하는 DOM의 Tailwind 클래스.

화면 스타일은 HTML Tailwind 유틸리티로 작성한다. 화면별 CSS 파일이나 인라인 `template`·`styles`는 사용하지 않는다. 공통 호스트 클래스 모음은 정적으로 작성해 Tailwind가 탐색할 수 있게 하며 `String.raw` 모음은 컴포넌트 속성의 `[class]` 바인딩으로 적용한다. Angular가 정적으로 해석해야 하는 `host.class`에 함수 호출 결과를 넣지 않는다.

Tailwind 권장 클래스 표기를 사용한다. 예를 들어 `[.notice_&]:font-bold`는 `in-[.notice]:font-bold`, `[top:0]`은 `top-0`, `[max-width:var(--content-max)]`는 `max-w-(--content-max)`로 작성한다. 권장 표기 경고를 설정으로 숨기지 않으며 불필요하게 반복된 클래스는 제거한다.

## 공통 컴포넌트

Select는 공통 `appInput`으로 input과 같은 테두리·44px 높이·10px 모서리·14px 텍스트·여유 있는 오른쪽 공간과 얇은 펼침 화살표를 사용한다. 네이티브 선택/키보드 조작을 유지하고 비활성·포커스 상태를 구분한다. 장소 검색 버튼은 돋보기 장식 없이 `검색` 텍스트로 통일하며 처리 중에는 버튼 안 스피너를 사용한다.

페이지 이동 로딩은 본문에 공간을 추가하지 않는다. 200ms 이상 지연될 때만 표시하고 이동 완료·취소·실패 시 제거한다. 짧은 이동에는 표시하지 않고 기존 화면의 배치와 조작을 유지한다. 표시는 3px 진행 막대이며 상단 바가 있으면 그 아래 테두리에 겹쳐 붙이고 없는 화면에서는 화면 맨 위에 둔다. 화면 가운데에는 아무것도 띄우지 않는다. 예전의 중앙 고정 표시는 그림자 진 흰 상자여서 카드 한 장이 떠 있는 것처럼 보였고, 상자를 벗겨도 본문 위에 얹힌 느낌이 남았다(2026-09-21 변경). 모션 감소 설정에서는 막대를 채운 상태로 고정한다.

뒤로가기 `〈`가 있는 화면은 상단 제목을 왼쪽 정렬한다. 공통 상단 바의 44px 뒤로가기 영역 다음 4px 간격에서 제목을 시작하며 여행 상세도 같은 위치를 사용한다. 긴 제목은 말줄임하고 오른쪽 동작 영역을 침범하지 않는다.

| 구성요소 | 사용 방식 | 계약 |
| --- | --- | --- |
| 버튼 | `button[appButton]`, `a[appButton]` | default/primary/ghost/danger/icon. disabled/loading이면 실행과 라우팅을 차단. 네이티브 폼·링크 의미 유지 |
| 입력 | `input[appInput]`, `select[appInput]`, `textarea[appInput]` | 네이티브 Forms·label 유지. 입력·선택 높이 44px, 모서리 10px. textarea는 여러 줄 높이 |
| 필드 | `app-field` | label/inputId/hint. 입력 id를 inputId와 맞추고 힌트가 있으면 aria-describedby를 `<inputId>-hint`에 연결 |
| 배지 | `span[appBadge]` | accent/place/region/stay/warn/danger/ok/meal/cafe/neutral. 상태 텍스트 필수. meal·cafe는 일정 분류 전용이며 완료(ok)·숙소(stay)와 뜻이 겹치지 않도록 따로 둔 색이다 |
| 안내 | `div[appNotice]` | warn/danger/ok. 동적 오류 등 필요한 경우에만 소비자가 live region 지정 |
| 로딩 | `app-spinner` | 장식용. 독립 로딩은 부모 role=status와 접근성 이름, 버튼은 aria-busy 제공 |
| 오류 토스트 | `app-error-toast` | message/dismissed. 하단 중앙·안전 영역·role=alert·닫기 버튼. 자동 소멸하지 않음 |
| 하단 동작 바 | `div[appActionBar]` | 하단 고정·안전 영역. 내부 action-bar__inner에 주요 버튼 배치 |
| 스위치 | `app-switch` | checked/disabled/label/changed. 누르는 즉시 반영되는 설정에 쓴다. 폼을 보내야 반영되는 자리에는 체크박스를 쓴다. 줄 전체가 버튼이면 `presentational`을 켜고 표시만 맡긴다 |

새 UI는 공통 컴포넌트를 우선 사용한다. variant를 추가하면 제품 사용처와 실험실 예제를 함께 갱신한다. 실험실에만 쓰이는 모사 컴포넌트를 만들지 않는다.

## 겹침 층위와 떠 있는 요소 (2026-09-22)

화면 위에 얹는 요소의 z 값은 아래 순서를 따른다. 값을 새로 정하지 말고 이 표에서 고른다. 지금까지 이 규칙은 `theme.css` 주석에만 있었다.

| 층 | z-index | 무엇 |
| --- | --- | --- |
| 하단 동작 바 | 10002 | `div[appActionBar]`. 화면마다 하나만 둔다 |
| 떠 있는 버튼 | 10004 | 동작 바 위에 뜨되 상단 바에는 가린다 |
| 상단 바 | 10006 | 페이지 이동 막대는 10007 |
| 팝오버·시트 배경 | 10010 | 상단 바와 동작 바를 모두 덮는다 |
| 팝오버·시트 본체 | 10011 | 자기 배경 위에 선다 |

팝오버나 시트를 새로 만들면 `theme.css`의 뒤 배경 스크롤 잠금 선택자 목록에 그 선택자를 추가한다. 목록에 넣지 않으면 열린 동안 뒤 화면이 함께 굴러 사용자가 어디를 보고 있는지 잃는다.

**떠 있는 버튼**은 지름 56px, 오른쪽 여백 16px, 하단 동작 바 위로 12px 띄운다. 안전 영역은 동작 바가 이미 처리하므로 그 위에 얹기만 한다. 본문 하단 여백을 확보해 목록의 마지막 항목을 가리지 않게 하고, 같은 자리에 뜨는 오류 알림은 `--toast-bottom-offset`을 올려 위로 민다.

이 버튼에는 공통 `appButton`을 쓰지 않는다. 공통 버튼의 호스트 클래스에 `relative`가 들어 있고 템플릿 `class`보다 나중에 적용되어 `fixed`를 덮는다. 떠 있는 버튼은 화면에 고정되는 것이 핵심이므로 스타일을 직접 준다.

**하단 시트**는 처음에 화면 높이의 62%로 열리고 손잡이를 눌러 92%로 넓힌다. 절반으로 두면 말풍선 두어 개와 입력창만 들어가 대화를 이어 가기 어렵다. 손잡이는 끌기와 함께 누르기로도 동작해야 한다. 끌기는 터치에서만 되고 키보드로는 쓸 수 없기 때문이다. `theme.css`의 `sheet-rise` 애니메이션을 쓰고 모션 감소 설정에서는 끈다.

전체 화면 대신 시트를 쓰는 기준은 **고치는 대상이 보여야 하는가**이다. 대상을 보면서 고치는 일은 시트로, 대상이 아직 없는 일은 전체 화면으로 연다.

## 대화 화면 (2026-09-22)

말풍선은 글자 길이만큼만 차지한다. 사용자는 오른쪽 `accent-tint`, AI는 왼쪽 `ground-2`를 쓰고 말꼬리 쪽 모서리만 작게 깎는다. 최대 폭은 사용자 80%, AI 88%이며 넓은 화면에서는 대화 전체를 640px로 가둔다. 글줄이 화면 끝까지 늘어나면 눈이 다음 줄 첫머리를 찾지 못한다.

**확인 카드**는 강조색 2px 테두리로 말풍선과 구분한다. 읽고 넘기는 답변과 달리 눌러서 결정해야 하는 것이기 때문이다. 바뀌기 전과 후를 2열로 나란히 두고, 빠지는 줄에는 취소선과 투명도를, 더해지는 줄에는 굵기와 강조색을 준다. 이동 거리 변화는 `ok-ink`로 별도 줄에 적되 0.1km 미만이면 적지 않는다. 그 정도 차이는 직선 거리 계산의 오차 범위라 알릴 뜻이 없다.

**확인되지 않은 정보**는 `warn` 계열로 감싸고 위에 `AI 답변 · 부정확할 수 있습니다`를 둔다. `danger`를 쓰지 않는 이유는 "틀릴 수 있다"는 뜻이지 "잘못되었다"는 뜻이 아니기 때문이다. 아래에는 네이버 지도와 카카오맵 링크를 함께 둔다. 이 표시는 챗봇만의 것이 아니라 영업정보를 보여주는 모든 화면의 공통 규칙이며 `app-ai-disclaimer`로 쓴다.

**빈 대화**에는 무엇을 할 수 있는지 한 줄로 알리고 추천 칩으로 예시를 보여준다. 빈 입력창만 두면 무엇을 물어도 되는지 몰라 그 앞에서 멈춘다. 칩은 입력창 바로 위에 두며 좁은 화면에서는 가로로 구르고 720px 이상에서는 줄바꿈한다.

## 상호작용과 접근성

- 버튼 로딩은 문구를 유지하고 내부 스피너·중복 실행 차단으로 표현한다. ‘화면으로 이동 중’ 같은 별도 문장을 추가하지 않는다.
- 스피너는 `animate-spin`과 `border-r-transparent`로 열린 테두리를 회전시킨다. border shorthand가 투명 부분을 덮지 않게 한다. 모션 감소 설정은 `motion-reduce:animate-none`으로 존중한다.
- 토스트는 짙은 배경·흰 본문·오류 아이콘을 사용하며 44px 닫기 영역을 확보한다. 모바일 하단 안전 영역을 반영한다.
- 작은 아이콘 버튼도 조작 영역은 최소 44px로 확보한다. 키보드 포커스를 숨기지 않는다.
- **상태에 따라 값이 바뀌는 자리는 `[class.left-5]`가 아니라 `[style.left.px]`를 쓴다.** Tailwind는 소스에서 클래스 문자열을 찾아 CSS를 만드는데, `[class.xxx]` 표기는 그 문자열이 나타나지 않아 규칙이 만들어지지 않는다. 화면에서는 아무 일도 일어나지 않고 오류도 나지 않는다(2026-09-17 스위치 손잡이에서 확인). 색처럼 두 값 중 하나를 고르는 경우도 `[style.background]`에 토큰을 넣는다.
- 아이콘과 글자를 한 줄에 놓을 때는 아이콘을 감싼 칸에 `size-5` 같은 고정 크기를 준다. 크기를 주지 않으면 아이콘마다 폭이 달라 글자 시작 위치가 어긋난다.
- 지도 마커·순번·날짜 선택은 목록과 같은 상태를 표시한다. 방문 순서 안내선은 실제 경로로 설명하지 않는다.
- 미확인 위치·시각·숙소와 저장 오류는 숨기지 않는다. 오류 후 입력을 유지하고 재시도를 제공한다.
- 모바일 360px와 PC에서 가로 넘침·고정 버튼에 가려진 내용·키보드 조작을 확인한다.

펼쳐진 select 목록은 지원 브라우저에서 `appearance: base-select`와 `::picker(select)`로 앱 폰트·둥근 패널·선택 배경을 적용한다. 미지원 브라우저는 네이티브 목록으로 동작한다. [브라우저 지원 및 선택 동작 참고](https://developer.mozilla.org/en-US/docs/Learn_web_development/Extensions/Forms/Customizable_select).

날짜·시간도 같은 input 토큰(테두리·44px 높이·10px 모서리)을 사용한다. 공통 TemporalPicker는 지연 로드하며 앱 폰트와 둥근 패널을 제공한다. 날짜는 월 이동·방향키·min/max 범위를 지원하고 시간은 시/분(필요시 초) 선택 후 적용한다. 네이티브 입력 유형과 폼 검증·직접 입력은 유지한다. 기본 버튼과 하단 행동 버튼의 실제 높이는 모두 44px이며 작은 보조 버튼·아이콘 버튼은 별도 규격이다.

여행 기간은 한 박스·한 달력에서 시작일과 종료일을 이어 선택한다. 선택 범위는 연한 배경, 양 끝은 강조색으로 표시한다. 입력 하단 설명은 공통 6px 간격·12px 글자·1.45 줄 높이와 `hint` 색상(#707782)을 사용하며 일반 설명과 오류 색상을 구분한다. 필드 내부 gap과 설명 margin을 중복 적용하지 않는다.

기간 달력 상단의 시작일/종료일은 테두리 입력 박스 대신 하나의 날짜 요약 행으로 표시한다. 작은 라벨과 한국어 날짜, 가운데 방향 표시, 현재 선택 단계의 하단 강조선으로 구분한다. 반복 안내는 스크린리더 상태 안내로 유지한다.

기간 입력창의 좌우 패딩은 일반 input과 같은 12px이며 내부 날짜 필드에는 중복 패딩·배경을 적용하지 않는다. 설명과 숙박 일수 라벨 사이에는 8px 간격을 둔다. 달력 범위 배경은 빈틈 없이 연결하고 시작·종료 및 주 행의 양 끝을 둥글게 표시한다. 선택한 날짜 숫자는 원형 강조색으로 구분한다.

## 2026-09-19 지도 선명도 보정과 데스크톱 균형

앞선 밝기 보정만으로는 지도가 여전히 흐리게 보였다. 실제 화면에서 흰 지형이 탁한 베이지로 떨어져 연한 바다와 구분되지 않았고 초록 군집도 번진 얼룩처럼 읽혔다. 원인은 ACESFilmic 톤 매핑이 흰색을 회색 쪽으로 눌렀기 때문이므로 톤 매핑을 제거하고 광량만으로 밝기를 맞춘다.

- 톤 매핑은 `NoToneMapping`으로 두고 반구광 1.55·환경광 0.62·방향광 1.15로 낮춘다. 노출 보정값은 사용하지 않는다.
- 지형은 순백 대신 지도 전용 `map-land`를 쓴다. 순백은 하이라이트가 날아가 입체감이 사라진다.
- 바다는 흰 지형과 윤곽이 구분될 만큼만 내린다. 방문 초록은 옅은 단계에서도 범례 칩과 같은 채도로 보이게 올린다.
- 데스크톱에서는 지역별 방문 목록을 오른쪽 열의 두 번째 카드로 두어 지도 높이와 맞춘다. 모바일은 지도 → 범례 → 선택 안내 → 지역 목록 순서를 유지한다. 목록은 항상 펼쳐 두고 접이식 `details`는 쓰지 않는다.
- 방문하지 않은 지역은 색 점만으로 구분하지 않고 글자색을 보조색으로 낮춰 함께 표시한다.

## 2026-09-21 통계 화면 정리와 방문색 변경

방문색을 초록에서 청록으로 옮긴다(`map-visit-low #c9eaf0` · `middle #3fb3c9` · `high #0d5563`). 바다와 계열이 이어져 지도가 한 덩어리로 보이며, 완료(`ok`)·지역(`region`) 초록과 뜻이 겹치지 않는다. 사용자가 여섯 가지 후보를 비교해 고른 값이다. 지형과 바다 토큰, 단계 구분과 입체 높이는 그대로 둔다.

지도 밖 화면은 다음을 따른다.

- **마커**: 알약 라벨과 작은 점 하나로 두고 지형을 가리지 않게 한다. 누르면 활성 표시만 바꾸고 지도 위에 창을 띄우지 않는다. 선택한 지역의 내용은 오른쪽 패널이 맡으므로 같은 정보를 두 곳에 두지 않는다. 보이는 크기와 별개로 조작 영역 44px은 투명 여백으로 확보한다.
- **범례**: 막대 다섯 개 대신 이어진 띠 한 줄과 양 끝 라벨(`1회`·`21회 이상`)을 쓴다. 단계가 눈금이 아니라 연속으로 읽힌다.
- **월별 방문**: 막대는 딥 블루를 쓴다. 지도의 방문색을 월별 값에 쓰면 같은 색이 두 가지 뜻을 갖는다.
- **최근 방문한 장소**: 같은 핀을 반복하지 않고 최근 순서를 번호로 보여 준다. 1번만 채운 배지로 구분한다.
- **지역 목록**: 다녀온 곳과 아직 안 간 곳을 나눈다. 안 간 곳은 작은 칩으로 접어 실제 기록이 묻히지 않게 한다. 선택은 행 배경을 칠하지 않고 왼쪽 세로 막대와 글자색으로 표시한다.
- **기록이 없을 때**: 범례·지역 목록·커버리지 수치를 감춘다. 0회 목록과 `0%`는 알려 주는 값이 아니라 없음을 강조할 뿐이다. 대신 세 단계 안내와 여행 만들기를 둔다.
- **지도 높이**: 지역을 고르기 전에는 크게(`clamp(460px, 74svh, 820px)`), 고른 뒤에는 오른쪽 기록에 맞춰 줄인다(`clamp(420px, 60svh, 640px)`).

## 2026-09-21 지도 조작과 입력 폭 정정

- **격자 지역 배정**: 칸 하나는 한 지역에만 든다. 어느 지역인지 찾을 때 작은 지역부터 본다. 광역시는 도에 둘러싸여 있고 단순화된 경계에서는 두 폴리곤이 겹치므로, GeoJSON 순서대로 찾으면 앞에 있는 도가 늘 이긴다. 그 탓에 광주가 격자에서 통째로 사라졌다.
- **스크롤 양보**: 지도는 세로를 크게 차지하므로 한 손가락과 휠을 페이지에 넘긴다. 지도 이동과 확대는 두 손가락, 그리고 화면의 +/− 버튼이 맡는다. 휠은 OrbitControls보다 먼저 받아 전파만 끊고 `preventDefault`는 하지 않아 기본 스크롤이 살아 있다.
- **select 폭**: 공통 select는 화살표 자리로 오른쪽 44px을 쓴다. 폭을 강제할 때 그만큼을 빼고 글자가 들어갈 자리를 계산한다. `w-24`(96px)는 글자에 40px만 남겨 '2024년'이 잘렸다.
- **빠진 기록 안내**: 집계되지 않은 여행의 까닭은 지역 목록 아래에도 둔다. 화면 끝 작은 글씨로만 두면 값이 비어 보이는 자리에서 답을 찾을 수 없다.
- **폼 히스토리**: 저장이나 삭제를 마친 폼은 `replaceUrl`로 치운다. 그대로 두면 뒤로 갔을 때 이미 처리한 입력 화면이 다시 나타난다.
