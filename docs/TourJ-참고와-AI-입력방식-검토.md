# TourJ 참고와 AI 일정 입력 방식 검토

2026-09-09 · 참고 조사 및 미확정 제안. 기존 기획·OpenSpec의 5단계 입력을 확정 변경하거나 제품 코드를 수정하지 않았다.

## 확인한 대상

사용자가 말한 ‘TORUJ’는 검색상 가장 일치하는 여행 앱 **TourJ(뚜르제이)**로 해석했다. 다른 앱이면 참고 대상을 다시 확인한다.

- [공식 App Store 소개](https://apps.apple.com/kr/app/id6772987674)
- [Apple 공식 조회 API](https://itunes.apple.com/lookup?id=6772987674&country=kr)의 iPhone 스크린샷 주소에서 소개 이미지 9장을 내려받았다.
- 시각 검토는 `output/playwright/tourj-reference/store-1.jpg`~`store-4.jpg`의 일정·AI 생성·초대·담아두기 소개 화면이다. 앱스토어 홍보 이미지 속 화면이며 실제 앱 실행·탭 전환·입력 저장·AI 생성은 검증하지 않았다. 프로모션 바깥 배경과 실제 앱 화면을 구분한다.

## 관찰

- 소개 이미지 속 앱 상단은 하늘색에서 라벤더로 이어지는 그라데이션이다. 흰 카드·매우 옅은 바탕과 함께 쓰며, 주요 추가 버튼과 선택된 하단 탭에도 유사한 강조가 있다.
- 일정 카드의 보조 행동은 펼치기·더보기로 묶여 있다. 현재 우리 앱의 항상 노출된 반복 편집 버튼을 줄일 때 참고할 수 있다.
- AI 생성 소개 화면은 기본 여행 정보와 여러 조건을 한 화면에 모으고 각 조건 옆에 펼치기 표시를 둔다. 이전 설정을 재사용하는 동작과 입력 완료 수가 보인다. 접이식 구성으로 해석되지만 실제 조작은 미검증이다.
- 공식 설명에도 추천 장소 중 원하는 장소를 골라 추가하는 기능이 있다. 선택 담기를 모든 경쟁 앱에 없는 기능으로 표현하지 않는다. ‘처음 전체 선택’ 여부는 이 소개만으로 확인하지 못했다.

## 우리 앱에 적용할 디자인 제안

트리플의 간결한 정보 위계에 TourJ에서 확인한 부드러운 그라데이션을 결합하는 방향을 제안한다.

- 여행 헤더와 AI 만들기 진입 카드에는 얕은 하늘색→라벤더 그라데이션을 사용한다. 현재 파란 강조색과 연결할 수 있지만 정확한 색상은 미확정이다.
- 지도·일정·정산 본문은 밝고 단순한 바탕과 흰 카드로 유지한다. 그라데이션은 강약을 주는 제한된 영역에 둔다.
- 선택은 색뿐 아니라 체크·윤곽·선택 문구로 구분한다. 그라데이션 버튼의 글자는 가장 밝은 구간에서도 읽히는지 확인한다.
- 장소별 상태색·지도 마커색·선택 색이 서로 경쟁하지 않게 한다. 이미 발견한 첫 장소의 노출 위치와 반복 버튼 문제를 먼저 해결한다.
- TourJ 캐릭터·로고·사진·문구를 제품 자산으로 복제하지 않는다.

## AI 입력 방식 비교

| 방식 | 장점 | 우리 앱에서의 부담 |
| --- | --- | --- |
| 한 화면에 모두 펼침 | 모든 조건을 훑고 바로 수정 가능 | 복수 지역·숙소까지 포함하면 모바일 폼이 길어짐 |
| 질문마다 별도 단계 | 첫 사용자에게 다음 할 일이 명확함 | 반복 생성·수정에도 여러 번 이동해야 함 |
| 첫 생성은 짧은 단계, 수정은 요약 화면 | 첫 입력 안내와 빠른 재수정을 함께 제공 | 같은 입력 상태·검증을 두 표현에서 공유해야 함 |

**추천은 첫 생성 3단계 + 조건 요약, 이후 한 화면 수정이다.** 이는 검증 전 설계 제안이며 기존 5단계의 확정 변경이 아니다.

1. 여행 기본: 복수 지역·방문 순서와 날짜/기간. 날짜 미정도 허용한다.
2. 여행 스타일: 동행·이동수단·일정 밀도·관심사. 짧은 선택 묶음과 기본값·건너뛰기를 사용하며 세부 질문을 강제하지 않는다.
3. 고정 조건: 꼭 갈 장소·기존 숙소/예약·추가 요청. 없으면 건너뛰고 기존 여행에서는 저장된 조건을 먼저 보여준다.
4. 요약: 조건을 한 화면에서 확인하고 해당 묶음을 눌러 직접 수정한 뒤 [AI 일정 만들기]로 요청한다.

재생성은 이전 값을 채운 요약 화면에서 시작해 필요한 조건만 수정한다. 처음부터 모든 단계를 반복하지 않는다. 이 화면은 편집 가능한 요약이므로 모든 입력을 항상 펼치지는 않는다. PC에서도 같은 상태·검증을 사용하고 넓은 화면에는 요약을 옆에 보조 표시할 수 있다.

AI는 최종 만들기에서만 호출한다. 단계 이동·체크 변경·요약 편집은 호출하지 않는다. 결과의 검증된 방문 항목은 기본 전체 선택하며 사용자가 해제 후 명시적으로 담는다. 단계 뒤로가기·실패 시 입력을 보존하고 기존 숙소·고정 일정은 보호한다.

## 방향 확정 후 검증할 것

- 모바일 첫 사용자에게 필수 입력과 건너뛸 항목이 구분되는가.
- 이전 설정에서 조건 하나를 바꿀 때 처음부터 이동하지 않는가.
- 단계형과 요약 편집이 날짜·지역·숙소 데이터를 동일하게 보존하는가.
- 그라데이션을 추가해도 장소 가독성·상태 대비·지도 조작이 유지되는가.
- 확정 시 기획안 25절·Triple 분석·OpenSpec 입력 요구사항·CLAUDE.md·PRODUCT.md·DESIGN.md를 함께 갱신한다.
