# 개발 범위·진행·검증 안내

문서 경로 표기는 별도 링크가 없는 경우 프로젝트 루트 기준이다. 공통 규칙은 [AGENTS.md](../AGENTS.md), 아키텍처와 상태관리는 [ARCHITECTURE.md](../ARCHITECTURE.md), 전체 목차는 [문서 안내](README.md)를 따른다. 이 문서는 개발 범위·진행 순서·검증 안내의 원본이며 CLAUDE.md에는 중복 작성하지 않는다.

## 시작할 때

- 한국어로 소통하고 사용자의 최신 지시를 우선한다.
- 구조·상태관리 작업은 `ARCHITECTURE.md`를 따른다. 최신 사용자 결정은 Angular 21 업그레이드 + NgRx Signals 21.x + 기능별 구조다. 현재 설치된 Angular 20과 목표 버전을 구분한다. 공식 마이그레이션·기존 흐름 검증 후 상태를 분리하며 Zoneless는 별도 검증한다. Signal Forms·rxResource는 21에서 experimental이므로 의무 규칙으로 복사하지 않는다. 이행 작업은 OpenSpec tasks 9절이며 기반 업그레이드 후 지도→AI→Supabase 순서를 유지한다.
- `docs/기획안-v0.1.md`를 읽는다. 특히 16~18절의 숙소·복수 지역·AI 초안과 19~23절의 기본 흐름·출시 순서를 확인한다.
- AI 일정·디자인 작업은 `docs/트리플-맞춤일정-분석.md`와 기획안 25절을 먼저 확인한다. 트리플과 유사한 단계 질문·지도/날짜 탭/카드/고정 버튼 구조를 참고한다. 시각 체계는 2026-09-09 사용자가 선택한 ‘클린 앱 표준’(미지근한 회백색 바탕, 흰 카드·1px 구분선, 밑줄 탭, Noto Sans KR 한 가족, 코랄 강조 하나)이며 PRODUCT.md·DESIGN.md가 원본이다. 추천 결과는 처음에 모든 검증된 방문 항목이 선택되고, 해제 후 [선택한 장소 N개 일정에 담기]로 확정한다. 기본 전체 선택과 자동 저장을 혼동하지 않는다. 실제 공개 웹을 확인한 분석이며 네이티브 앱 전체를 검증한 것은 아니다.
- `openspec/changes/plan-travel-companion-mvp/`의 `proposal.md`, `design.md`, `tasks.md`, `specs/` 아래 요구사항 문서를 읽는다. 변경이 보관되거나 경로가 바뀌었다면 현재 OpenSpec 상태에서 대응 문서를 찾는다.
- `docs/알파-화면설계-v0.1.md`(화면별 입력·빈 상태·오류·저장 결과, 구현 작업, 검증 시나리오)와 `app/`의 실제 코드·테스트를 확인한다. 문서의 기획 상태를 현재 구현 상태로 단정하지 않는다.
- 구현 요청을 받으면 화면별 입력·빈 상태·오류·저장 결과와 구현 작업을 구체화한 뒤 아래 범위부터 진행한다. 기획 수정 요청만 받았으면 기획 문서 수정에 집중한다.

## 첫 구현 범위와 순서

최신 착수 지시: 현재 진행 중인 작업을 먼저 완료하고 사용자가 이후 별도로 요청할 때 ARCHITECTURE.md에 따른 리팩터링·Angular 21 업그레이드를 진행한다. 아래 업그레이드 우선순위는 그 후속 작업 내부의 순서이며 현재 기능 작업을 중단하라는 뜻이 아니다. 착수 때 최신 코드와 완료된 작업을 확인해 작업 범위를 다시 맞춘다.

첫 목표는 수동 일정 관리 내부 알파다. ‘여행 생성 → 수동 장소 1개 → 숙소 1개 → 날짜별·전체 보기 → 같은 기기에 저장 후 재열기’와 아래 항목은 2026-09-09에 `app/`(Angular 20)에 구현하고 Vitest·Playwright로 검증했다(OpenSpec tasks 3절). 최신 지시는 Angular 21 기반 업그레이드와 검증(tasks 9.1)이며, 기능 우선순위는 지도·장소·경로 연결(tasks 7절) → 선택형 AI 실제 연동·화면(tasks 6절) → Supabase 연결(tasks 4절)이다. 상태·폴더 정리는 관련 기능을 수정할 때 점진적으로 수행한다. 기존 구현을 확인한 뒤 이어서 수정한다.

- 날짜 미정 초안, 미배치 장소, 시작일·종료일과 당일·여러 박 여행.
- 복수 지역, 하루 두 지역, 연박·숙소 변경·숙소 미정, 체크인·체크아웃 날짜와 선택 정보.
- 수동 장소 추가·수정·제외·날짜 배치·순서 변경, 체류시간·메모·고정 조건.
- 식사·휴식·여유시간, 이동·체류 중복 합산 방지, 전체/날짜별/숙소 보기와 충돌 표시.
- 저장 상태·실패 입력 보존·재시도, 확인된 목적지의 외부 지도 연결과 주소 복사 대안.

실제 검색·경로 연동은 별도 실증한다. 키가 없으면 수동 입력과 명확히 표시한 샘플로 흐름을 구현하되 실제 연동 완료로 보고하지 않는다. 위치·이동시간이 미확인인 항목은 미확인으로 유지한다.
AI 추천·숙소 초안·부분 수정은 수동 알파 다음 단계다. 로그인·기기간 동기화·오프라인 충돌 해결·사진 지도·캐릭터·주변 탐색·여행 중 지연 대응은 후속 작업으로 분해한다. 실시간 3D·홍보 영상·Higgsfield는 첫 구현 의존성이 아니다.
프레임워크는 현재 Angular 20이며 최신 사용자 결정으로 Angular 21로 업그레이드한다. 설계 기준과 근거는 기획안 12·29절, ARCHITECTURE.md와 OpenSpec design.md에 있다. 실제 설치·마이그레이션·검증 전에는 업그레이드 완료로 표시하지 않는다. 추가 기술 선택은 기존 환경을 확인하고 근거를 기록한다. 공개 배포·유료 계정 사용은 별도 결정 사항이다. 상세 범위·예외·단계별 통과 기준은 기획안과 OpenSpec을 원본으로 유지한다.
DB는 Supabase PostgreSQL로 확정되었다. 초기 대상은 본인과 친구들이며 무료 플랜부터 시작한다. 로컬 저장은 초기 흐름 검증·비회원 초안 용도이며 친구들과 실제 사용하기 전 Supabase Auth·서버 저장·사용자별 RLS를 검증한다. 사진은 비공개 Storage에 분리하고 스키마 변경은 마이그레이션으로 관리한다. 공동 편집과 복잡한 오프라인 동기화는 후속 범위다.
초기 설계·임시 저장 화면 구현 다음에는 실제 지도·장소·경로와 선택형 AI를 먼저 연결해 화면을 검증한다(기획안 26절). Supabase 프로젝트는 아직 없으며 이후 로그인·서버 저장·RLS를 연결한다. 화면은 `TripRepository` 인터페이스를 유지하며 친구들의 실제 사용 전 서버 저장·권한을 검증한다. AI와 비공개 장소/경로 API는 로컬 개발용 서버 엔드포인트를 두고 비밀키를 Angular 번들에 넣지 않는다. 지도 표시·장소 검색·경로 계산·AI 생성은 서로 다른 연동이며 하나의 MCP나 키로 모두 된다고 가정하지 않는다. 제공자별 어댑터와 `.env.example`을 준비하고 계정 인증·비밀키 입력이 필요한 시점에 안전한 로컬 입력을 안내한다. 실제 호출에 필요한 제공자·비용 범위는 확인하며 유료 계약을 임의 체결하지 않는다.

## 문서 변경

추가 UI 요구는 기획안 28절의 D-day·N박 N일·지역 구분·지출·동행 프로필이다. `AA.png`는 아직 확인되지 않았으므로 이미지 확인 후 배치를 정한다. 동행 초대는 링크뿐 아니라 8자리 코드로 여러 친구가 참여를 요청하고 로그인·소유자 승인 후 접근하는 방식도 제공한다(tasks 8.5·8.6). 초대 기능 연결 전에도 프로필 영역을 준비하되 가상 참여자·가짜 지출을 실제 값처럼 표시하지 않는다.

공유·정산 추가 기획은 `docs/기획안-v0.1.md` 27절과 OpenSpec tasks 8절·5절을 따른다. 지도 → AI → Supabase 이후 동행·공유 권한 → 가계부·정산 순서로 구현한다. 선택한 일정의 읽기 전용 링크, 승인된 동행의 조회, 결제자·부담 대상별 계산과 수동 수령 기록이 1차 범위다. 공동 일정 편집·자동 송금은 제외하며 공유·정산에는 AI 호출이 필요 없다. 기존 소유자 RLS 검증을 유지하고 비공개 필드 누출·멤버 제거·정산 중복 저장·변경 후 잔액을 추가 검증한다. 추가 기획을 구현 완료로 표시하지 않는다.

기획 변경 시 기획안과 관련 OpenSpec 문서를 함께 수정하고, 착수 범위가 달라지면 이 문서의 첫 구현 안내도 갱신한다. 공통 작업 규칙은 `AGENTS.md`를 따른다. 파일 간 동기화는 자동화되어 있지 않으므로 작업 중 직접 비교·수정하고 결과를 확인한다.

## 도구와 검증

프로젝트 MCP는 Claude Code의 `.mcp.json`과 Codex의 `.codex/config.toml`에 각각 설정한다. Context7은 라이브러리 문서 조회용이다. Supabase는 현재 문서 조회만 설정되어 있으며 OAuth 로그인과 개발용 project ref 지정 전에는 DB 연결 완료로 취급하지 않는다. 프로젝트 지정 후 필요한 도구 그룹만 활성화하고 두 설정을 함께 갱신한다. 현재 상태와 연결 절차는 `docs/HARNESS.md`를 확인한다.

프로젝트 스킬은 `.agents/skills/`에 있다. 필요한 `SKILL.md`를 읽어 적용하고 실제 사용 가능한 도구를 확인한다. `docs/HARNESS.md`의 설치 기록만으로 현재 실행 가능성을 단정하지 않는다.
실제 제품 화면은 Impeccable(PRODUCT.md·DESIGN.md·`.impeccable/surfaces/` 방향 계약 준수), 브라우저 검증은 Playwright(`app/e2e/`, `npm run e2e`)를 사용한다. 실행 명령과 포트·저장 키 분리는 README와 `docs/HARNESS.md`를 따른다. 완료 보고에는 변경 파일·실행 방법·실제 검증 결과·남은 작업을 포함한다.
날짜 계산, 기간 단축·지역 삭제 시 데이터 보존, 숙박 오류·충돌, 저장 실패·재열기를 검증한다. 360px 모바일과 키보드에서 조작하고 런타임 앱과 테스트 앱의 포트·저장소·테스트 데이터를 분리한다. 실제 지도앱 설치/미설치와 사용자 수행 목표는 샘플·자동 테스트 결과와 구분한다. OpenSpec 작업은 실제 결과가 확인된 항목만 완료한다.

## 개발 시작 요청 예시

“CLAUDE.md와 연결된 기획안·OpenSpec을 읽고 현재 저장소를 확인해 내부 알파 개발을 진행해줘. 화면별 동작과 구현 작업을 구체화한 뒤 첫 구현 흐름부터 작은 단위로 구현·검증하고, 완료 범위·검증 결과·미연결 부분·남은 작업을 구분해 보고해줘.”
