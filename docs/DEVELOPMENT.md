# 개발 범위·진행·검증 안내

현재는 Angular 21·NgRx Signals·Zoneless 기반 내부 알파다. 문서 목차는 [README](README.md), 공통 작업 규칙은 [AGENTS.md](../AGENTS.md), 구조 원본은 [아키텍처](architecture/ARCHITECTURE.md), 요구사항은 [기획안](기획안-v0.1.md)과 [OpenSpec](../openspec/changes/plan-travel-companion-mvp/tasks.md)이다.

## 현재 구현

| 영역 | 구현·확인 범위 |
| --- | --- |
| 수동 일정 | 여행 생성·편집, 날짜 미정, 복수 지역, 장소·활동·숙소 배치, 전체/날짜별/숙소 보기, 충돌 표시, 같은 기기 저장·재열기 |
| 저장 안정성 | 여행별 저장 직렬화, 실패 초안 보존·재시도, 조회 응답 역전 방지 |
| 지도·장소 검색 | 카카오 제공자와 테스트 픽스처 구현. 실제 키 연동과 경로시간 조회는 각각의 실제 검증 결과로 판단 |
| AI | 조건 입력·샘플 추천·선택 담기 구현. 실제 LLM 연결·품질 검증은 후속 |
| 계정 | Supabase Google·카카오 인증, 닉네임 온보딩, 내 정보·로그아웃, 운영 인증 가드, 하단 오류 토스트·버튼 로딩 |
| 회원탈퇴 | 본인 계정 삭제 서버 코드와 확인 UI 구현. 서버 미배포로 런타임 비활성 |
| 디자인 시스템 | 전 화면 Tailwind, HTML/TS 분리, 공통 UI, 실험실 `/lab`, 컴포넌트별 폴더와 `-page` 없는 파일명 |

Google·카카오 제공자 로그인 화면 도착까지 확인했다. 실제 사용자의 인증 완료·닉네임 서버 저장은 모의 응답 테스트와 구분한다. 여행은 아직 기기 저장이며 계정별 서버 저장·RLS가 연결된 상태가 아니다.

## 다음 개발 범위

1. 지도·장소 검색 실데이터와 경로 조회 범위를 확인한다. 미확인 위치·영업정보·이동시간을 추측해 채우지 않는다.
2. 실제 LLM과 선택형 AI를 연결한다. 서버 엔드포인트와 친구 PC 연결 절차는 [LOCAL-LLM.md](LOCAL-LLM.md)를 따른다.
3. Supabase 여행 저장·사용자별 RLS·저장 충돌 처리와 회원탈퇴 배포를 검증한다. Auth 연결만으로 이 단계를 완료하지 않는다.
4. 서버 권한 검증 후 동행·읽기 전용 공유, 경비·정산을 구현한다. 사진·기록·캐릭터는 후속 범위다.

사용자 요청으로 소셜 인증과 디자인 시스템을 선행 구현했다. 친구들이 실제 데이터를 넣기 전에 서버 저장·권한을 검증한다. 공개 배포·유료 계약은 별도 결정 사항이다.

## 실행과 디자인 확인

명령은 [프로젝트 README](../README.md), 연동 설정은 [HARNESS.md](HARNESS.md)를 따른다.

- `npm start`: 4200의 development 앱. `designPreview=true`로 로그인 없이 여행·온보딩·계정 화면을 확인한다. 미리보기는 실제 세션을 만들지 않는다.
- `npm run e2e`: 4300의 test 앱. 별도 저장 키·지도 픽스처·모의 인증을 사용하고 인증 가드를 유지한다.
- production도 인증 가드를 유지한다. development 설정을 변경했다면 서버를 재시작한다.
- 디자인 원본은 [DESIGN.md](design/DESIGN.md), 실행 토큰은 `app/src/styles/theme.css`, 실제 예제는 `/lab`이다.

## 검증 기준

단위 테스트는 날짜·숙박·기간 변경·저장 실패·상태 경쟁을 검증한다. 브라우저에서는 여행 편집·재열기, 인증·닉네임·로그아웃, 키보드 조작, 360px 화면, 공통 UI·스피너를 확인한다. 런타임 앱과 테스트 앱의 포트·저장소를 분리하고 캡처는 Git에서 제외된 `output/playwright/`에 둔다.

검증 결과의 원본은 [OpenSpec 작업 현황](../openspec/changes/plan-travel-companion-mvp/tasks.md)이다. 2026-09-14 기록은 단위 85개, 전체 브라우저 92개 통과 후 스피너 관련 10개 추가 통과, 운영 빌드·69모듈 경계 검사 통과다. 문서 편집 시 과거 실행 결과를 새로 실행한 결과로 표시하지 않는다.

## 현재 우선 작업: 디자인과 기획 병행

공통 UI 갱신: 이동 로딩은 레이아웃을 밀지 않는 200ms 지연 중앙 표시다. select·날짜·시간 입력은 같은 테두리·44px 높이·10px 모서리이며 날짜/시간은 공통 선택창과 직접 입력을 함께 지원한다. 기본/하단 행동 버튼 실제 높이를 44px로 통일했다. select 펼침 패널 스타일은 지원 브라우저에서 적용하고 미지원 브라우저는 네이티브 목록을 유지한다. 장소 검색은 텍스트 `검색`과 버튼 내부 로딩을 사용한다.
친구 초대·공유 미리보기, 일정 예상 비용, 실제 지출 가계부, PNG 저장 화면을 기존 디자인 시스템으로 구현한다. DB 연결은 하지 않는다. 현재 기기 저장·미리보기와 실제 친구 초대/공동 편집을 구분한다. 실행 항목은 OpenSpec tasks 12절이며 서버 저장·권한은 디자인 확정 후 진행한다.


현재 로컬 UI: 개별 여행 상세 상단은 `뒤로 · 여행 이름 · 편집 연필 · 참여자 이니셜 · 초대 + · 더보기` 순서로 배치한다. 편집은 숨기지 않으며 가계부는 일정 옆 탭, 이미지 저장은 더보기 메뉴에 둔다. 현재 기기에서는 로그인한 본인의 닉네임만 표시하며 실제 동행 목록은 서버 연결 후 제공한다. 본문 동행 영역과 큰 도구 버튼 나열은 사용하지 않는다. 실제 지출 CRUD·참여자 이름·균등/직접 분담·개인 지출·부분 수령/취소 기록은 기기별로 저장한다. 예상 비용은 일정에 별도로 입력하고 실제 금액에 자동 합산하지 않는다. PNG는 전체/날짜별로 저장하며 예상 비용 포함을 선택한다. 실제 초대 링크·서버 권한·공동 편집은 미구현이다.

검증 갱신: 단위 90개·경계 82모듈, 전체 E2E 92/94 후 로그인 로딩 검사 수정 및 관련 8개 통과, 새 기능 PC/360px 흐름·PNG 다운로드 검증 통과. 실행 범위와 미구현 서버 기능은 OpenSpec tasks 12절에서 구분한다.
로그인 화면 하단의 `로그인 없이 둘러보기`는 모바일 화면 검토를 위한 임시 미리보기 버튼이다. 누른 브라우저 세션에서만 여행 화면 가드를 건너뛰며, 운영 인증 흐름과 실제 계정·권한 검증은 유지한다.
