# 내부 알파 화면 설계 v0.1 (수동 일정 관리)
작성일: 2026-09-09 · 상태: 구현 기준 문서(디자인은 사용자 확정 방향으로 교체됨, PRODUCT.md·DESIGN.md 참조) · 원본 기획: `docs/기획안-v0.1.md` 16~23절, OpenSpec `plan-travel-companion-mvp`

이 문서는 기획안 19~23절과 OpenSpec 요구사항을 **첫 구현 범위(수동 일정 관리 내부 알파)** 의 화면별 입력·빈 상태·오류·저장 결과로 구체화한다. AI 추천, 숙소 AI 초안, 실제 장소 검색·경로 조회, 로그인·서버 저장, 사진 지도, 캐릭터는 이 문서의 범위 밖이며 후속 단계에서 별도 설계한다.
후속 AI 일정 화면은 `docs/트리플-맞춤일정-분석.md`·기획안 25절·OpenSpec tasks 6절을 따른다. 사용자 결정은 ‘트리플과 유사한 흐름·구조, 결과는 기본 전체 선택 후 개별 해제·선택한 항목만 담기’다. 해당 후속 명세를 기존 수동 알파의 구현 완료로 취급하지 않는다.

## 0. 기술 선택과 근거
- **프레임워크**: Angular 20 (standalone 컴포넌트, signals, Angular Router). 기획안 12절은 Next.js를 후보로 두었을 뿐 확정하지 않았다. 사용자 작업 환경에는 Angular CLI 20.3.8이 전역 설치되어 있고 기존 프로젝트(signal-todo, household-ledger)가 모두 Angular 20 기반이므로, 유지 관리 부담과 추가 설치 없이 시작할 수 있는 Angular를 선택한다. 반응형 웹/PWA와 Supabase 연동에는 두 후보 모두 제약이 없다.
- **저장 계층**: 화면은 `TripRepository` 인터페이스만 사용하고, 알파에서는 `LocalStorageTripRepository`가 이를 구현한다. Supabase 연결 단계에서 같은 인터페이스를 구현하는 저장소로 교체한다. 임시 저장 단계에서는 서버 동기화 기능을 미리 구현하지 않는다.
- **도메인 로직**: 날짜 계산, 숙박 검증, 전체 보기 요약, 기간 변경 영향 계산은 프레임워크에 의존하지 않는 순수 TypeScript 모듈로 두고 Vitest로 단위 검증한다.
- **브라우저 검증**: Playwright(`@playwright/test`). 런타임 앱은 4200 포트와 `tc.trips.v1` 저장 키를, 테스트 앱은 4300 포트와 `tc.test.trips.v1` 저장 키를 사용해 데이터를 분리한다.
- **디자인**: 제품 화면은 Impeccable 절차를 적용한다. PRODUCT.md·DESIGN.md는 저장소 루트에 둔다. 2026-09-09 리뉴얼로 시각 방향은 사용자가 세 후보 중 선택한 “클린 앱 표준”(회백색 바탕·흰 카드·1px 구분선·밑줄 탭·Noto Sans KR·코랄 하나)이며 근거는 `.impeccable/surfaces/app-src-app-features-trips.md`에 있다.

## 1. 데이터 관계와 소유권

### 1.1 엔터티
| 엔터티 | 필드 | 비고 |
| --- | --- | --- |
| `Trip` | `id`, `title`, `startDate?`, `endDate?`, `regions[]`, `stops[]`, `stays[]`, `status`, `createdAt`, `updatedAt`, `schemaVersion` | 날짜는 `YYYY-MM-DD`. 둘 다 없으면 날짜 미정 초안. `status`는 알파에서 `draft` 고정 |
| `TripRegion` | `id`, `name`, `order` | 여행 안의 순서 있는 지역. 일정 정리용 정보이며 날짜를 지역에 종속시키지 않음 |
| `TripStop` | `id`, `kind`(`place`/`meal`/`break`/`buffer`), `name`, `address?`, `regionId?`, `date?`, `order`, `stayMinutes?`, `memo?`, `fixedTime?`, `excluded`, `locationStatus`(`unverified` 고정) | `date`가 없으면 미배치. `excluded`는 일정에서 제외하되 삭제하지 않음 |
| `AccommodationStay` | `id`, `name`, `address?`, `regionId?`, `checkIn`, `checkOut`, `checkInTime?`, `checkOutTime?`, `reservation`(`unknown`/`reserved`/`not_reserved`), `memo?`, `locationStatus`(`unverified` 고정) | 숙박 날짜 구간은 체크인 포함·체크아웃 제외. 시각이 없으면 미정 |

### 1.2 소유권과 저장
- 알파의 모든 데이터는 **같은 기기의 비회원 초안**이며 소유자는 그 기기 사용자다. 저장소 단위는 `Trip` 하나(하위 지역·장소·숙소 포함)이며 `trips` 컬렉션에 `id`로 저장한다.
- Supabase 전환 시 `Trip`은 `owner_id`를 갖고 RLS로 소유자만 읽고 쓴다. 하위 엔터티는 `trip_id`로 소유권을 상속한다. 이 문서의 필드명은 서버 테이블 설계의 초안이며 실제 마이그레이션은 연결 단계에서 작성한다.
- `TripStop`과 후속 `Visit`/`Photo`는 분리한다. 알파에는 `Visit`이 없으므로 장소 제외·삭제가 기록에 영향을 주지 않는다.
- 저장 상태는 `idle` / `saving` / `saved` / `error`로 구분해 화면에 표시한다. 저장 실패 시 화면의 입력값과 메모리의 최신 상태를 유지하고 [다시 저장]을 제공한다.

## 2. 화면 목록과 이동
```
/trips                 트립플로 목록
/trips/new             여행 만들기
/trips/:id             여행 상세 (전체 / 날짜별 / 숙소 탭)
/trips/:id/edit        여행 기본 정보·기간·지역 편집
/trips/:id/stops/new   장소·활동 추가
/trips/:id/stops/:sid  장소·활동 편집
/trips/:id/stays/new   숙소 추가
/trips/:id/stays/:aid  숙소 편집
```
모달 대신 라우트 페이지를 사용한다. 360px 모바일에서 한 화면에 하나의 작업만 두고, 모든 조작은 버튼과 키보드로 가능하게 한다(드래그 없음).

## 3. 화면별 명세

### 3.1 트립플로 목록 `/trips`
- **입력**: 없음. [새 여행] 버튼.
- **표시**: 여행 카드(제목, 기간 요약 `5월 1일 – 5월 5일 · 4박 5일` 또는 `날짜 미정`, 지역 이름 나열, 장소 n개 · 숙소 n개). 최근 수정순.
- **빈 상태**: “아직 만든 여행이 없습니다” + 첫 여행 만들기 안내 + [새 여행].
- **오류**: 저장소를 읽지 못하면 “기기 저장소를 읽지 못했습니다” + [다시 시도]. 손상된 항목은 건너뛰고 개수를 표시한다.
- **저장 결과**: 해당 없음(읽기 전용).

### 3.2 여행 만들기 `/trips/new` · 편집 `/trips/:id/edit`
- **입력**: 제목(기본값 “새 여행”, 수정 가능), 시작일, 종료일(둘 다 선택 사항), 지역 목록(이름 입력 후 [추가], 목록에서 [위로]/[아래로]/[삭제]).
- **파생 표시**: 두 날짜가 모두 있으면 `N박 N+1일`을 즉시 표시한다. 당일이면 `0박 1일`.
- **오류**:
  - 종료일이 시작일보다 빠르면 “종료일은 시작일과 같거나 이후여야 합니다” 표시, 저장 차단.
  - 시작일만 또는 종료일만 있으면 “두 날짜를 모두 입력하거나 모두 비워 두세요” 표시, 저장 차단.
  - 제목이 비어 있으면 “새 여행”으로 대체한다.
- **편집 시 기간 변경 영향**: 새 기간 밖으로 밀려나는 배치 장소와 숙박이 있으면 영향 목록(“3개 장소가 미배치로 이동, 숙소 B가 기간 밖”)을 보여주고 [영향을 확인했습니다] 체크 후 저장한다. 장소는 미배치(`date=null`)로 보존하고 숙박은 그대로 보존하되 상세에서 ‘기간 밖’으로 표시한다. 어떤 항목도 자동 삭제하지 않는다.
- **편집 시 지역 삭제 영향**: 삭제할 지역을 참조하는 장소·숙소가 있으면 개수를 표시하고, 삭제 후 해당 항목의 `regionId`를 비운다(장소·숙소 자체는 보존).
- **저장 결과**: 저장 성공 시 상세로 이동. 실패 시 폼을 유지하고 오류 배너 + [다시 저장].

### 3.3 여행 상세 `/trips/:id`
- **머리글**: 제목, 기간 요약(또는 “날짜 미정”), 지역 순서, 저장 상태 표시(“기기에 저장됨 · 방금” / “저장 중” / “저장 실패 · 다시 저장”), [편집].
- **탭**: [전체] [날짜별] [숙소]. 날짜 미정 여행에서는 [날짜별] 탭 대신 “날짜를 정하면 날짜별 일정을 만들 수 있습니다” 안내와 [날짜 정하기](편집으로 이동)를 보여준다.
- **빈 상태(방금 만든 여행)**: 전체 탭에 “장소와 숙소를 추가해 보세요” + [장소 추가] [숙소 추가].
- **오류**: id에 해당하는 여행이 없으면 “여행을 찾을 수 없습니다” + [목록으로].

#### 3.3.1 전체 보기
- 날짜마다 한 줄 요약: `1일차 · 5월 1일(금) · 강릉` → 주요 일정(배치 장소 이름을 순서대로, 최대 4개와 “외 n개”) → 그날 밤 숙소(`A 숙소 체크인` / `A 숙소 연박` / `A 체크아웃 → B 체크인` / `숙소 미정` / 마지막 날은 `귀가일`).
- 보조 정보: 체류 합계(장소·활동 `stayMinutes` 합), 이동 구간 수와 “이동시간 미확인 n구간”(경로 조회가 없으므로 항상 미확인), 충돌 배지.
- 날짜 줄을 누르면 날짜별 탭의 해당 날짜로 이동한다.
- 하단 “미배치 장소” 목록: 날짜가 없는 장소·활동. 각 항목에 [날짜 배치](편집으로 이동).
- 충돌·확인 필요 목록: 숙박 날짜 중복, 기간 밖 숙박, 고정 시각 순서 불일치, 위치 미확인 항목 수. 항목을 누르면 해당 편집으로 이동.

#### 3.3.2 날짜별 보기
- 날짜 탭(가로 스크롤, 키보드 좌우 이동). 선택 날짜의 지역(그날 배치 장소·숙소의 지역을 순서대로 표시. 하루에 두 지역이면 둘 다 표시).
- 그날의 숙소 정보 카드: 전날 밤 숙소 체크아웃(있으면), 그날 밤 숙소 체크인 또는 연박, 미정이면 “이 날 밤 숙소 미정”과 [숙소 추가].
- 시간순 항목 카드: 종류 표시(장소/식사/휴식/여유), 이름, 지역, 체류시간, 메모 요약, 고정 시각(있으면 자물쇠 표시), 위치 미확인 표시. 조작: [위로] [아래로] [편집] [제외/복원]. 제외 항목은 흐리게 표시하고 합계에서 뺀다.
- 항목 사이에 “이동 · 시간 미확인” 구분선. 지역이 바뀌는 구간은 “강릉 → 속초 이동 · 시간 미확인”으로 표시한다(중복 합산 없음).
- 하루 합계: “체류 합계 3시간 30분 · 이동 4구간 미확인”. 도착 시각은 제시하지 않는다.
- 빈 상태: “이 날 일정이 없습니다” + [장소 추가] [식사·휴식 추가].
- 각 항목 카드의 [지도 열기]는 이름(과 주소)으로 네이버 지도·카카오맵 웹 검색을 새 탭에서 연다. [주소 복사]는 주소가 있을 때만 활성화하며 클립보드 실패 시 주소를 선택 가능한 텍스트로 보여준다. 좌표가 없으므로 검색 링크임을 표시한다.

#### 3.3.3 숙소 보기
- 밤별 표: `1박 5/1 밤 → A 숙소`, `2박 5/2 밤 → A 숙소(연박)`, `3박 5/3 밤 → 미정`. 마지막 날은 밤이 없다. 당일 여행은 “당일 여행은 숙박이 없습니다”만 표시한다.
- 숙소 목록 카드: 이름, 체크인·체크아웃 날짜와 N박, 시각(미정이면 “시각 미정”), 예약 상태, 지역, 메모, 위치 미확인, [편집] [삭제]. 삭제는 확인 단계를 거친다.
- 충돌: 같은 밤에 두 숙박 → 두 카드 모두 “다른 숙박과 중복” 배지. 기간 밖 → “여행 기간 밖” 배지. 날짜 미정 여행의 숙박은 “여행 날짜 미정: 숙박 날짜는 확인 대상” 표시.
- 빈 상태: “등록된 숙소가 없습니다. 숙소 미정인 밤이 있어도 일정은 저장됩니다.” + [숙소 추가].

### 3.4 장소·활동 추가/편집 `/trips/:id/stops/new`, `/trips/:id/stops/:sid`
- **입력**: 종류(장소/식사/휴식/여유시간), 이름(장소는 필수, 식사·휴식·여유는 기본 이름 “식사”/“휴식”/“여유시간”), 주소(선택), 지역(선택, 여행 지역 중 선택), 날짜(선택; 여행 기간 내 날짜 목록 또는 “미배치”), 체류시간(분, 선택, 0 이상), 메모(선택), 고정 시각(선택, `HH:mm`).
- **빈 상태**: 여행 지역이 없으면 지역 선택을 숨기고 “여행 편집에서 지역을 추가할 수 있습니다” 안내.
- **오류**: 장소 이름이 비면 “장소 이름을 입력하세요”. 체류시간이 음수·숫자 아님이면 “0 이상의 분 단위로 입력하세요”. 저장 차단.
- **위치 상태**: 실제 검색 연동이 없으므로 모든 항목은 “위치 미확인”으로 저장하고 화면에 표시한다. 샘플이나 추정 좌표를 넣지 않는다.
- **저장 결과**: 새 항목은 선택 날짜의 마지막 순서로 추가. 편집 후 날짜를 바꾸면 새 날짜의 마지막 순서로 이동. 저장 후 상세의 날짜별(배치) 또는 전체(미배치) 탭으로 복귀. 실패 시 폼 유지 + [다시 저장].
- **삭제**: 편집 화면의 [삭제]는 확인 후 영구 삭제. 일정에서만 빼려면 [제외]를 안내한다.

### 3.5 숙소 추가/편집 `/trips/:id/stays/new`, `/trips/:id/stays/:aid`
- **입력**: 숙소 이름(필수), 주소(선택), 지역(선택), 체크인 날짜(필수), 체크아웃 날짜(필수), 체크인 시각·체크아웃 시각(선택, 비우면 미정), 예약 여부(미정/예약함/미예약), 메모(선택).
- **파생 표시**: 두 날짜가 유효하면 `N박` 표시.
- **오류(저장 차단)**: 이름 없음 → “숙소 이름을 입력하세요”. 체크아웃이 체크인과 같거나 이전 → “체크아웃 날짜는 체크인 다음 날 이후여야 합니다”.
- **확인 필요(저장 가능, 확인 체크 필요)**: 여행 기간 밖(일부 또는 전부) → “숙박이 여행 기간(5/1–5/5) 밖입니다”. 기존 숙박과 밤이 겹침 → “A 숙소(5/1–5/3)와 5/2 밤이 겹칩니다”. 두 경우 [확인하고 저장]을 체크해야 저장된다. 날짜 미정 여행에서는 기간 검사를 건너뛰고 “여행 날짜를 정한 뒤 다시 확인됩니다”를 표시한다.
- **저장 결과**: 상세의 숙소 탭으로 복귀. 실패 시 폼 유지 + [다시 저장].

### 3.6 저장 상태와 실패 처리(공통)
- 모든 쓰기는 저장소 서비스가 처리하고 결과를 `saveState` 시그널로 노출한다. 상세 머리글과 폼 하단에 표시한다.
- localStorage 예외(용량 초과, 접근 불가)는 `error`로 잡고 메모리 상태를 유지한다. [다시 저장]은 같은 데이터로 재시도한다. 성공하면 `saved`로 바꾼다.
- 재열기: 앱을 새로고침하거나 목록에서 다시 열면 저장소에서 읽어 동일한 내용을 표시한다.

## 4. 도메인 규칙 요약(단위 검증 대상)
1. `nights(start,end) = diffDays`, `days = nights + 1`. 당일은 0박 1일.
2. `enumerateDays(start,end)`는 시작·종료 포함. 종료 < 시작이면 오류.
3. 숙박 유효성: `checkOut > checkIn`. 숙박 밤 목록은 `[checkIn, checkOut)`.
4. 두 숙박이 같은 밤을 포함하면 중복. 숙박 밤이 여행 밤 목록 `[start, end)` 밖이면 기간 밖.
5. 밤별 숙소 표: 여행의 각 밤에 대해 숙박 0개면 미정, 1개면 해당 숙소, 2개 이상이면 충돌.
6. 날짜별 숙소 정보: 그날 체크아웃하는 숙박, 그날 체크인하는 숙박, 그날 밤 연박 여부(전날 밤과 같은 숙박).
7. 하루 합계: 제외되지 않은 배치 항목의 `stayMinutes` 합. 이동 구간 수 = 항목 수 − 1(0 이상). 지역이 바뀌는 구간은 별도 표시하되 합산은 한 번만.
8. 고정 시각 충돌: 같은 날 순서상 앞 항목의 고정 시각이 뒤 항목의 고정 시각보다 늦으면 충돌.
9. 기간 변경 영향: 새 기간 밖 날짜의 장소는 미배치로 이동, 숙박은 유지하되 기간 밖 표시. 지역 삭제 시 참조만 해제.
10. 순서 변경: 같은 날짜 안에서 위/아래 교환. 처음/끝에서는 비활성.

## 6. 검증 시나리오(Playwright)
1. **첫 흐름**: 새 여행(5/1–5/3, 지역 강릉) → 장소 1개(1일차) → 숙소 1개(5/1–5/3) → 날짜별·전체·숙소 보기 확인 → 새로고침 후 동일 내용.
2. **당일 여행**: 5/1–5/1 → “0박 1일”, 숙소 탭에 숙박 없음 안내.
3. **날짜 미정 → 확정**: 날짜 없이 생성, 장소 2개 미배치 → 편집에서 날짜 설정 → 미배치 유지, 날짜별 탭 활성.
4. **3박 4일 두 지역·두 숙소**: 강릉 A 5/1–5/3, 속초 B 5/3–5/4 → 밤별 표 A, A(연박), B / 3일차에 A 체크아웃·B 체크인 표시. 3일차에 강릉·속초 장소 배치 → “강릉 → 속초 이동” 1회 표시.
5. **숙박 오류·중복**: 체크아웃 ≤ 체크인 저장 차단. 5/2–5/4 추가 시 중복 경고 → 확인 후 저장 → 두 카드에 중복 배지.
6. **기간 단축 보존**: 5/1–5/4를 5/1–5/2로 → 영향 목록 → 확인 → 3·4일차 장소가 미배치로 이동, 숙소 B 기간 밖 배지, 삭제 없음.
7. **순서·제외·합계**: 2개 장소 위/아래 이동, 제외 시 합계 감소.
8. **저장 실패·재시도**: 저장소 쓰기를 실패하도록 주입 → “저장 실패” 표시와 입력 보존 → 복구 후 [다시 저장] 성공.
9. **360px·키보드**: 360×740 뷰포트에서 첫 흐름을 Tab/Enter만으로 수행하고 가로 스크롤이 없음을 확인.

실제 지도앱 설치/미설치, 처음 사용자 5명 중 4명 수행 목표는 자동 테스트로 대체하지 않으며 별도 실기기 검증 항목으로 남긴다.

## 7. 지도·장소 검색 (2026-09-09 추가, tasks 7.1~7.2)
- **제공자**: 카카오맵 JavaScript SDK(지도)·services 키워드 검색(장소). 앱은 `MapProvider`·`PlaceSearchProvider` 인터페이스만 쓰고, 테스트 앱은 픽스처 구현(외부 호출 없음)을 주입한다. 키는 `app/public/app-config.json`에서 읽는다.
- **장소·숙소 폼의 검색 상자**: 입력(검색어, Enter/검색 버튼) → 상태: 제공자 확인 중 / 연결 안 됨(사유·직접 입력 안내) / 검색 중 / 결과 목록(이름·분류·주소) / 결과 없음 / 오류(다시 검색). 결과를 고르면 이름·주소·좌표·제공자 참조가 채워지고 ‘위치 확인됨 · 제공자’ 칩과 [위치 지우기]가 보인다. 검색 없이 저장하면 ‘위치 미확인’.
- **날짜별 지도**: 확인된 좌표의 활성 항목만 일정 순번 그대로 번호 마커, 그날 체크아웃·숙박 숙소는 숙소 마커. 순번 마커를 잇는 점선은 ‘방문 순서 안내선 · 경로 아님’으로 표기한다. 상태: 제공자 확인 중 / 불러오는 중 / 연결 안 됨(키 파일 안내) / 오류 / 표시할 위치 없음. 범례에 ‘지도에 없음 n개 · 위치 미확인’을 표시한다.
- **동기화**: 마커 클릭 → 해당 카드 강조·스크롤. 카드 순번 클릭 → 마커 강조(다시 클릭 시 해제). 날짜 탭 이동 시 그날 마커로 교체. 제외 항목은 마커에서 빼되 순번은 유지한다.
- **숙소 탭 지도**: 확인된 좌표의 모든 숙박을 숙소 마커로 표시(안내선 없음).
- **검증**: 픽스처로 Playwright 4건(검색→선택→저장·마커·안내선·미확인 카운트·동기화·재열기, 결과 없음, 위치 지우기, 숙소 마커). 실제 카카오 키 검증은 별도 기록.
