# 트리플 맞춤 일정 분석과 우리 앱 적용안

확인일: 2026-09-09 · 상태: 참고 분석 및 후속 화면 설계 · 제품 코드 구현 완료를 뜻하지 않음

## 1. 확인 범위와 근거

원문: https://triple.guide/trips/promotion/customized-schedule

별도 로그인 없는 브라우저에서 홍보 화면(1440×1000, 390×844), 5단계 추천 질문, 추천 결과와 날짜 탭을 직접 조작했다. 테스트 조건은 강릉·속초, 3박 4일, 친구 동행, 자연·휴식 취향, 여유로운 일정이다. 실제 여행 예약이나 개인 일정 저장은 수행하지 않았다.
ADB로 확인한 연결 안드로이드 기기는 없다. 따라서 아래 내용은 공개 웹 흐름의 관찰이며 네이티브 앱 전체를 검증한 결과가 아니다. 페이지의 ‘맞춤 일정’ 표시만으로 내부에서 어떤 AI·추천 알고리즘을 쓰는지는 확인할 수 없다.

## 2. 직접 관찰한 입력 흐름

| 단계 | 확인된 동작 | 우리 앱에 적용 |
| --- | --- | --- |
| 시작 | 짧은 가치 설명, 지도·번호 마커 이미지, 하단의 주 행동 버튼 하나 | 긴 소개 없이 일정 만들기 진입. 반복 사용자는 소개를 거치지 않음 |
| 1/5 지역 | 국가별 도시 목록에서 한 도시 선택. 강릉·속초는 묶인 항목 | 국내 복수 지역 선택과 방문 순서 지원. 강릉·속초도 필요하면 따로 배치 |
| 2/5 기간 | 당일부터 5박 6일까지 기간 버튼 | 실제 날짜 또는 기간 미정 입력 유지, 긴 여행은 직접 기간 입력 가능 |
| 3/5 동행 | 동행 유형 다중 선택 | 동행 유형 칩, 선택하지 않고 진행 가능. ‘혼자’와 다른 유형의 모순 처리 |
| 4/5 취향 | 여러 관심사를 다중 선택 | 짧은 취향 칩과 선택적 요청 한 줄. 이미 입력한 내용 보존 |
| 5/5 밀도 | 촘촘한 일정과 여유로운 일정 중 선택 | 일정 밀도와 이동수단을 함께 받되 밀도 선택으로 임의 이동시간을 만들지 않음 |

마지막 질문은 이동수단이 아닌 일정 밀도였다. 기존의 ‘지역→날짜→동행→취향→이동수단’ 구상은 우리 제품의 변형이며 트리플에서 그대로 확인한 순서로 인용하지 않는다.

결과에서는 지역·기간 요약, 실제 지도 위 번호 마커, Day 1~4 탭, 순번·작은 사진·이름·분류·지역·추천 설명이 있는 세로 카드를 확인했다. 식사와 숙소도 일정 흐름에 들어간다. Day 3 탭 전환을 확인했다. 하단 고정 담기와 목록 끝의 담기·재추천·처음부터 다시 시작하는 동작이 보인다. 확인한 웹 결과에는 장소별 체크박스가 없으며 담은 일정은 앱에서 확인한다는 안내가 있다. 실제 담기 이후의 로그인·앱 편집·저장 방식은 검증하지 않았다.

## 3. 디자인에서 가져올 것

홍보 화면은 아주 밝은 바탕 위에 짙고 굵은 제목·옅은 설명·중심 이미지로 위계를 만든다. 질문 화면은 상단 뒤로가기와 우측 진행 숫자, 작은 의미 아이콘, 중앙 질문, 2열 둥근 선택 버튼, 하단 고정 주 버튼으로 구성된다. 질문 화면에서는 선택 항목의 윤곽선·글자색으로 상태를 구분한다. 결과는 상단 지도, 날짜 탭, 둥근 흰 카드와 얕은 그림자, 카드 왼쪽 번호, 하단 고정 담기로 위계를 이어간다.

우리 앱은 이 구성과 간결함을 따른다. 기존 PRODUCT.md의 따뜻한 크림 바탕·코랄 강조와 둥근 형태는 유지한다. 트리플의 로고·문구·사진·일러스트를 제품 자산으로 가져오지 않고, 캡처는 분석 근거로만 보관한다.

| 요소 | 우리 화면 기준 |
| --- | --- |
| 질문 화면 | 상단 뒤로가기 + 단계 숫자·단계명, 질문 하나와 짧은 설명, 선택 카드, 하단 다음 버튼 |
| 카드 상태 | 선택 시 체크·윤곽선·텍스트로 함께 표현. 색만으로 구분하지 않음 |
| 모바일 | 충분한 터치 영역, 긴 한글 줄바꿈, 안전 영역·키보드에 가리지 않는 하단 동작. 360px에서 검증 |
| 데스크톱 | 질문은 읽기 쉬운 폭으로 중앙 정렬. 결과는 지도와 목록을 나란히 사용 |
| 장식 | 의미 아이콘·작은 마커 중심. 반복 편집 화면에 큰 홍보 이미지나 불필요한 입장 애니메이션을 넣지 않음 |
| 접근성 | 표준 버튼·체크박스·라벨, 키보드 조작, 명확한 포커스. 시각적 카드와 의미 구조 일치 |

## 4. 우리 추천 입력 흐름

사용자 요청에 따라 단계형 선택을 기본으로 하고 자유 텍스트는 보조로 둔다. 직접 수동 일정 만들기는 별도 진입점으로 계속 제공한다.

1. **지역**: 하나 이상 지역 선택과 순서. 기존 여행에서 시작하면 현재 값을 채운다.
2. **날짜·기간**: 실제 시작·종료일 또는 아직 날짜 미정. 박수 빠른 선택은 입력 편의이며 최대 기간 제한이 아니다. 날짜 없이 기간만 고르면 결과는 실제 날짜 대신 Day 1…의 초안이며 적용 시 날짜를 확인하거나 미배치로 보관한다.
3. **동행**: 동행 유형 선택 또는 건너뛰기. 인원 정산·개인정보 수집을 이 단계에 끼워 넣지 않는다.
4. **취향**: 복수 관심사와 선택적 추가 요청. 미선택도 일반 후보 탐색으로 진행 가능하다.
5. **이동·일정 밀도**: 차량/도보/미정과 여유 정도. 마지막에 조건 요약을 확인하고 추천 요청한다. 기존 숙소·고정 예약은 요약에 유지하며 새 숙소 등록은 선택 사항이다.

뒤로가기·단계 이동으로 선택을 초기화하지 않는다. 지역·날짜 변경으로 숙소나 결과가 영향을 받으면 표시하고 확인한다. 로딩은 실제 진행 상태로 안내하며 정해진 초 수나 허위 진행률을 보장하지 않는다. 실패·취소 시 입력을 유지하고 재시도 또는 수동 작성으로 연결한다.

## 5. 핵심 차이: 처음에는 전체 선택, 담기는 사용자 결정

사용자가 설명한 트리플의 전체 일정 담기와 달리, 우리 앱은 결과를 선택 가능한 추천 초안으로 보여준다. **현재 추천 결과의 모든 검증된 방문 항목을 처음에 선택**하되 일정에는 아직 저장하지 않는다. 더 보기용 대안 후보·미검증 장소·기존 확정 숙소는 이 전체 선택 대상에서 제외한다.

상단에는 조건 요약과 선택 수, 전체 선택/해제를 둔다. 날짜별 구분 아래 각 장소의 체크박스·순번·사진(사용 가능할 때)·이름·추천 이유·체류 계획값을 보여준다. 날짜별 선택/해제와 부분 선택 상태를 제공한다. 상세 열기와 체크 동작을 분리한다.
하단 버튼은 **[선택한 장소 N개 일정에 담기]**다. 모든 날짜에 걸친 선택 수를 집계하며, 아무것도 선택하지 않았으면 비활성화하고 선택 안내를 표시한다. 버튼을 누르기 전에는 기존 여행·숙소가 바뀌지 않는다.

- 체크를 해제한 항목은 흐리게 표시하되 다시 선택할 수 있다. 날짜 탭 이동·상세 확인 후 복귀해도 선택을 유지한다.
- 선택 상태는 장소 식별자가 아닌 추천 결과의 방문 항목 단위로 관리한다. 같은 장소를 다른 날짜에 방문하는 계획은 별개다.
- 전체 선택은 현재 결과의 모든 날짜에 적용하며 현재 화면에 보이는 항목만 선택하지 않는다.
- 해제 즉시 알려진 체류 합계와 선택 수를 갱신한다. 영향을 받은 이동 구간은 재확인 필요로 표시하고 경로 조회를 항목 클릭마다 호출하지 않는다. [이동 다시 확인] 또는 담기 전 검증으로 갱신한다. 계산 전 절약 시간을 확정하지 않는다.
- 해제한 장소는 경로에서 빼고, 지도에서 후보로 남길 때는 선택된 일정과 구분한다. 지도·목록의 순번과 선택 상태를 일치시킨다.
- ‘비슷한 곳으로 교체’는 새 후보를 보여준 뒤 사용자가 교체를 확인한다. 기존 선택을 몰래 초기화하거나 해제한 항목을 재선택하지 않는다.
- 전체 재추천은 현재 선택에 미치는 영향을 확인받고 새 결과로 전환한다. 유지 가능한 항목은 선택 상태를 보존하고 새 후보는 추가된 항목임을 표시한다. 새 결과 전체 선택 초기화는 이를 확인한 경우에만 수행한다.
- 담기 직전 대상 여행·날짜별 배치·기존 일정과의 중복/충돌을 확인한다. 같은 결과를 반복 적용하거나 네트워크 요청이 재전송되어도 이중 저장하지 않는다. 이미 담은 항목과 다른 날짜의 의도적 재방문을 구분한다.
- 담기 실패 시 초안과 체크 상태를 유지한다. 성공 후 기존 여행 상세로 이동하며 되돌리기는 기획안 20절 규칙을 따른다.

첫 화면 ‘전체 선택’은 저장 동의나 추천 데이터 검증 완료를 대신하지 않는다. 숙소 초안은 기획안 18절의 숙박 기간 확인을 거치며 방문지 담기에 몰래 포함하지 않는다.

## 6. 구현 전달과 검증

이번 분석은 기존 Angular 20 수동 알파에 이어 만들 AI 추천 화면의 설계 기준이다. 기존 알파의 구현·검증 이력과 구분하고 새 요구사항을 완료 처리하지 않는다. 지도 SDK·경로 연동은 기존 후속 우선순위를 따르며, AI 미연결 화면에서는 샘플임을 표시한다.

검증: 처음 전체 선택, 하나 해제 후 나머지만 저장, 날짜 간 선택 유지, 전체·날짜별 부분 선택, 0개 선택, 다른 날짜 같은 장소, 결과 재생성·교체, 오래된 경로 표시, 담기 실패·중복 적용, 기존 숙소 보존, 모바일 하단 버튼과 키보드 접근을 포함한다.
